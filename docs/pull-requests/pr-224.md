# [PR 224](https://github.com/vig-os/scitadel/pull/224) ci(release): publish crates via crates.io trusted publishing

The 0.8.0 release published to GitHub, but `publish-crates` failed with `403 Forbidden: authentication failed`. `CARGO_REGISTRY_TOKEN` was set on 2026-04-18, and crates.io tokens expire.

- `publish-crates.yml` now mints a short-lived crates.io token per run from the job's OIDC identity with `rust-lang/crates-io-auth-action` (pinned to v1.0.5, auto-revoked when the job ends), so there is no long-lived secret to expire.
- `CARGO_REGISTRY_TOKEN` stays as a fallback, so the job works under either setup.
- `docs/RELEASING.md` documents the one-time crates.io setup: one trusted publisher per crate, with owner `vig-os`, repository `scitadel`, workflow `publish-crates.yml` and environment `crates-io`.

Once one of the two credential paths is in place, 0.8.0 is published with:
```
gh workflow run publish-crates.yml --ref dev -f tag=0.8.0
```
