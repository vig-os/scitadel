# [PR 213](https://github.com/vig-os/scitadel/pull/213) fix(openalex): API key, Linux credential store, real error reporting

Fixes #212.

Three stacked defects that together made OpenAlex unusable on Linux.

## 1. OpenAlex API-key support

`api_key=<key>` now goes on **every** OpenAlex request — `search`, `fetch_work_by_id`, `fetch_works_by_ids`, `fetch_cited_by` (snowball) and the download OA-location lookup in `PaperDownloader`. Keyless requests are billed against a shared per-IP daily budget and start returning `HTTP 429 … Insufficient budget` once it is spent.

Every call now funnels through a single `fetch_from`, so no endpoint can drift out of sync again. `search` previously built its own client and skipped the status check entirely — that was defect 3's root cause.

**Untangling the naming.** `config.openalex.api_key` used to hold the *email*. `OpenAlexConfig` now has separate `email` and `api_key` fields, carried together as an `OpenAlexAuth` value so the adapter, download chain and TUI can't be handed different halves.

| Credential | Store key | Env var | Config |
|---|---|---|---|
| API key (metered) | `openalex.api_key` | `SCITADEL_OPENALEX_API_KEY` | `[openalex] api_key` |
| Polite-pool `mailto` | `openalex.email` | `SCITADEL_OPENALEX_EMAIL` | `[openalex] email` |

**Backward compatible.** Pre-0.8 configs still load: an address-shaped `api_key` (contains `@` — OpenAlex keys never do) is read as `email`, only when `email` is unset. `scitadel init` writes `[openalex] email = "…"` and never writes the key to disk. `scitadel auth login openalex` asks for both; press enter to skip the email.

## 2. A Linux credential backend

`scitadel auth login` died off macOS with `failed to run security CLI: No such file or directory`. The backend is now resolved at runtime:

| Backend | Selected when | Storage |
|---|---|---|
| `macos-keychain` | macOS with the `security` CLI | Login keychain (unchanged path) |
| `secret-service` | `secret-tool` on `$PATH` **and** a Secret Service that answers | GNOME Keyring / KWallet / KeePassXC |
| `file` | Nothing else available | `$XDG_CONFIG_HOME/scitadel/credentials.toml`, mode `0600` |

- Detection probes for a *reachable* service, not just the binary: with no D-Bus session `secret-tool` writes a diagnostic to stderr, which is the signal to fall back rather than fail every login.
- `scitadel auth status` prints `Credential store: <backend>`; `SCITADEL_CREDENTIAL_BACKEND` overrides the choice.
- **No secrets are logged or echoed.** Values are piped to `secret-tool` over stdin (never on argv, so never in `ps`). The file store is created `0600` up front and written via a temp file + rename, in a `0700` directory. `auth status` prints only key names and locations.
- `auth login` also accepts piped stdin now instead of requiring a tty (`rpassword` hard-failed with `No such device or address` on a pipe), so credentials can be provisioned non-interactively.

## 3. Adapter errors are never `0 results`

```
  [!] openalex: HTTP 429 Too Many Requests — Insufficient budget. This request has no API key… (58ms)
  [!] 1 of 2 source(s) failed (openalex) — results below are incomplete.
  [+] arxiv: 5 results (323ms)
```

- The failure is recorded on the search run (`SourceOutcome::Failed` + message), so it shows in `scitadel history` (`[!] failed: openalex`), in the MCP `search` payload (new `failed_sources` field) and in `list_searches`, and `scitadel export` warns on stderr that the run was incomplete.
- Other sources' results are untouched.
- The message carries the HTTP status plus a short excerpt of OpenAlex's `message`/`error` body, truncated to 200 chars.
- The request URL is deliberately **kept out** of the error string — it carries `api_key`, and this string lands in logs and the DB.
- `CoreError::Adapter`'s `adapter error: <source> — ` prefix is stripped in the orchestrator, since `outcome.source` already names the source.

## Tests

`cargo test --workspace` — **517 passed, 0 failed**. `cargo fmt --check` and `cargo clippy --workspace --tests -- -D warnings` both clean.

New coverage, by defect:

- **Query-param construction incl. `api_key`** — `crates/scitadel-adapters/src/openalex.rs`: key present on every endpoint shape, email stays `mailto` and never becomes the key, blanks omitted; plus error-body extraction/truncation.
- **HTTP behaviour (wiremock)** — `crates/scitadel-adapters/tests/openalex_http.rs` (8 tests): both credentials on the wire for search / by-id / cited_by / batch; **mock HTTP 429** → `Err` not empty results, with the status and upstream message in the error and the key *absent* from it; a 500 with an HTML body; keyless adapter sends only `mailto`; and an end-to-end orchestrator test where the 429 becomes a `Failed` outcome, a healthy sibling keeps its results, and the record round-trips through serde.
- **Credential backend selection** — `crates/scitadel-core/src/credentials.rs`: pure `select_backend` policy (macOS → secret-service → file, env override, unrecognised override ignored), file-store round-trip, `0600`/`0700` permissions, corrupt-store recovery, OpenAlex key/email requirements.
- **`auth` end to end** — `crates/scitadel-cli/tests/auth_backend.rs` (10 tests): backend named in status; login stores both OpenAlex credentials without echoing the key; optional email skippable; blank required credential rejected; logout clears; store is `0600`; **a Linux box with an empty `$PATH` (no `security`, no `secret-tool`) logs in successfully** — the exact #212 crash; a `secret-tool` stub proves the Secret Service path is preferred and round-trips over stdin; and a stub that can't reach D-Bus falls back to the file store.
- **Config migration** — `crates/scitadel-core/src/config.rs`: legacy email-in-`api_key` migrates, a real key doesn't, an explicit pair is never rewritten, idempotent.
- **CLI output** — `crates/scitadel-cli/src/commands.rs`: a failed source prints its error, a genuinely empty one still prints `0 results`.

## Live verification

NixOS, release binary, temp DB in a scratch dir, `secret-tool` absent (so the file backend is auto-selected — the #212 machine shape).

```
$ SCITADEL_OPENALEX_API_KEY=… scitadel search "DOTA lutetium" -s openalex -n 5
  [+] openalex: 5 results (1066ms)

$ SCITADEL_OPENALEX_API_KEY=definitely-not-a-real-key scitadel search "DOTA lutetium" -s openalex -n 5
  [!] openalex: HTTP 401 Unauthorized — API key not found (2268ms)
  [!] 1 of 1 source(s) failed (openalex) — results below are incomplete.

$ … -s openalex,arxiv        # other sources survive
  [!] openalex: HTTP 401 Unauthorized — API key not found (2068ms)
  [+] arxiv: 5 results (323ms)

$ scitadel history
  03d40b62  …  "DOTA lutetium"  5 papers  1/2 sources ok  [!] failed: openalex

$ scitadel export 03d40b62 -f json     # stderr
warning: search 03d40b62 had 1 failed source(s) (openalex) — this export is incomplete.

$ scitadel auth status
Credential store: file (…/credentials.toml, mode 0600)
$ printf '%s\nlars@…\n' "$KEY" | scitadel auth login openalex
  Stored: openalex.api_key
  Stored: openalex.email
$ scitadel auth status
      API key: file
  [+] openalex       configured
$ scitadel search "DOTA lutetium" -s openalex -n 5    # no env var — store only
  [+] openalex: 5 results (697ms)
$ stat -c '%a' credentials.toml
600
```

**One caveat, stated plainly:** the live 429 could not be reproduced right now — this IP's keyless daily budget was not exhausted at the time of testing, so the keyless run returned 200 (`[+] openalex: 5 results`) rather than an error. The 429 path is covered by the wiremock test and demonstrated live via the 401 above, which travels the identical code path (non-2xx → status + body excerpt → `SourceOutcome::Failed`). The 401 from a bogus key is also positive proof that `api_key=` reaches OpenAlex and is honoured.

## Notes

- `Cargo.lock` picks up the new `tempfile` dev-dependency on `scitadel-core`, and refreshes stale `0.6.0` workspace-member entries to `0.7.0` (they were already `0.7.0` in the manifests, so any build dirtied the tree).
- `credentials::get_keychain` is kept as a `#[deprecated]` alias for `credentials::get`.
- `MCP list_sources` now reports OpenAlex as configured only when the **key** is present; the polite-pool email alone is no longer enough, since keyless calls still 429.
