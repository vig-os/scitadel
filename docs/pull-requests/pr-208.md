# [PR 208](https://github.com/vig-os/scitadel/pull/208) chore(repo): upgrade devkit scaffold 0.3.3 -> 1.6.0 and migrate to the devkit release train

## Summary

cc @gerchowl — this migrates scitadel's release system, please review that part in particular.

Migrates scitadel off the legacy devkit 0.3.3 scaffold to **devkit 1.6.0**, and **replaces release-please with the devkit release train**:

- **Scaffold**: direnv delivery (repo-owned `flake.nix`/`.envrc` preserved; stale 0.3.3 `.devcontainer/` pruned), gitflow workflow (dev+main unchanged), full 1.6.0 workflow set incl. `devkit-upgrade.yml` (auto-upgrade from here on).
- **Release train migration**:
  - release-please retired (`release-please.yml`, config, manifest, bot-setup scripts/docs deleted); Dependabot config removed (Renovate is the devkit path).
  - **`prepare-release-extension.yml`** (mutating seam): replaces release-please's cargo-workspace version bumping — `cargo set-version --workspace` committed onto the release branch via commit-action, so published crates never carry a stale version.
  - **`release-extension.yml`** (read-only seam): crates.io publishability gate (metadata + leaf `cargo publish --dry-run`) at `finalize_sha` — fails before the version is burned.
  - **`publish-crates.yml`**: live publish moved to `release: published` (non-prerelease). Deliberately NOT in the seam: needs `CARGO_REGISTRY_TOKEN` + the `crates-io` environment gate, and crates.io publishes are irreversible — never from a pre-tag seam that can roll back.
  - **`binaries.yml`**: stays on tag push (final semver), now uploads into the draft Release (`--clobber`); the draft→published flip belongs to `promote-release.yml`. Immutable releases refuse assets after publish, so `release: published` was not an option.
  - Tag prefix stays **unprefixed** (`0.7.0` style — release-please config had `include-v-in-tag: false`; the old `v0.5.0`/`v0.6.0` tags are historical strays).
- **Flake**: `vigos` input pinned to the 1.6.0 tag + `overlays.default`, providing `uv` + `vig-utils` for ci.yml's commit-checks job; `pre-commit` → `prek`; absolute `CC`/`CXX` exported (devkit#1351 PATH-order bug; scitadel builds vendored sqlite via cc-rs).
- MIGRATION.md 0.3.x checklist worked; `justfile.project` recipes moved from dead pyproject-gated no-ops onto cargo.

## Verification

- `prek run --all-files` → exit 0 (verified independently after review)
- `just test` (`cargo test --workspace`) → **467 tests passed, 0 failed**
- CI commit-checks toolchain validated locally by replaying `setup-devkit-toolchain`'s PATH assembly: `prek`/`just`/`uv`/`validate-commit-range`/`check-pr-agent-fingerprints` all resolve

## Reviewer notes (judgment calls)

1. **`just-fmt` hook retired** — the shipped root justfile is not `just --fmt`-stable under this flake's just, and reformatting a managed file guarantees scaffold-drift failures. Nothing else used the hook.
2. **`LICENSE` (Apache-2.0) added by the scaffold** next to the existing dual `LICENSE-APACHE`+`LICENSE-MIT` — kept to satisfy the drift gate, but flag if you'd rather pursue a devkit exemption.
3. `.typos.toml` gained 8 allow-words on the 1.39→1.45 dictionary jump — all checked as genuine false positives, worth a skim.
4. `just test` now runs `cargo test --workspace` in CI without rust-cache — correct but slower than `rust-ci.yml`'s cached job; alternative was a vacuously green Tests job.
5. Small forced touches to go green: `yamllint truthy` disables in `rust-ci.yml`/`vhs.yml`, one pymarkdown-corruption fix in `tests/vhs/README.md`.
6. **Double version pin**: the `vigos` flake input (1.6.0 tag) is a second devkit-version site next to `.vig-os` — future `devkit-upgrade.yml` PRs bump only the latter, so each devkit bump needs a manual `nix flake update vigos` (the known direnv-consumer pattern).

## Before the first release train

- Resolve the `dev`-behind-`main` sync first (0.7.0 release is still Draft, `chore/sync-main-to-dev-6-1` open) — the train reads `CHANGELOG.md`, whose top entry on `dev` is 0.6.0.
- First release needs the one-time manual-promote runbook (devkit MIGRATION.md); documented in the rewritten `docs/RELEASING.md`.
- Open dependabot branches can be closed (Renovate takes over); stale `feature/wu*` / `rust-rewrite` / `release-please--branches--*` cleanup stays out of scope.

+#

+# calls this reusable workflow after finalize_sha is computed and before

+# release.yml, which triggers the consolidated rollback via `needs` — so this is

+#
+# This project uses it as the release-time backstop for crates.io publishing:
+# the workspace is only ever published from a tag, and a crate that is missing
+# required registry metadata (or no longer builds a valid .crate) can otherwise
+# only be discovered AFTER the tag exists — at which point the version is burned
+# and cannot be re-cut. publish-crates.yml runs the identical checks on every PR
+# to dev/main; this job re-runs them at inputs.finalize_sha, the exact commit the
+# tag will point at, so a merge cannot slip broken publish metadata past the PR
+# gate. Read-only (contents: read) — nothing is published here; the live publish
+# runs from publish-crates.yml once the GitHub Release is promoted.
+#
+# Both checks run for candidates as well as finals: an RC is the cheapest place
+# to learn that the workspace has stopped being publishable.
+#
+# Toolchain: this seam provisions the Rust toolchain directly
+# (dtolnay/rust-toolchain, as rust-ci.yml and binaries.yml do) rather than the
+# devkit dev-shell composite. The repo-owned flake carries the full interactive
+# dev shell (vhs, chromium, asciinema); building it here would cost far more than
+# the checks themselves. The workflow_call inputs contract below is fixed —
+# release.yml passes these by name.
+#
+# Token ceiling (#1144): release.yml's `extension` caller job grants this seam a
+# ceiling of contents:read, packages:write, id-token:write, attestations:write.
+# Nothing here needs more than contents:read.
+

+
+on:  # yamllint disable-line rule:truthy
+  workflow_call:
+    inputs:
+      version:
+        description: "Release version"
+        required: true
+        type: string
+      finalize_sha:
+        description: "Finalized commit SHA"
+        required: true
+        type: string
+      release_date:
+        description: "Release date"
+        required: true
+        type: string
+      release_kind:
+        description: "Release kind (candidate or final)"
+        required: true
+        type: string
+      publish_version:
+        description: "Version tag that will be published (X.Y.Z or X.Y.Z-rcN)"
+        required: true
+        type: string
+

+  contents: read
+

+    name: Verify crates.io publishability
+    runs-on: ubuntu-24.04
+    timeout-minutes: 30
+    permissions:
+      contents: read
+
+    steps:
+      - name: Checkout finalized commit
+        uses: actions/checkout@v6
+        with:
+          ref: ${{ inputs.finalize_sha }}
+          persist-credentials: false
+
+      - uses: dtolnay/rust-toolchain@stable
+      - uses: Swatinem/rust-cache@v2
+
+      - name: Check every crate has publishable metadata
+        # cargo-manifest-level check that each workspace crate carries the
+        # metadata crates.io requires. Does NOT hit the registry, so it also
+        # works for internal deps that are not published yet.
+        env:
+          PUBLISH_VERSION: ${{ inputs.publish_version }}
+        run: |
+          set -euo pipefail
+          missing=$(cargo metadata --no-deps --format-version 1 \
+            | jq -r '.packages[]
+                     | . as $p
+                     | ["description", "license", "repository"][]
+                     | select(($p[.] // "") == "")
+                     | "  - \($p.name): missing \(.)"')
+          if [ -n "$missing" ]; then
+            echo "Missing publish metadata (publishing $PUBLISH_VERSION):"
+            printf '%s\n' "$missing"
+            echo "::error::One or more workspace crates cannot be published to crates.io."
+            exit 1
+          fi
+          echo "All workspace crates carry the required publish metadata."
+
+      - name: Dry-run publish (leaf crate only)
