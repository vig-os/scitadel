# [PR 241](https://github.com/vig-os/scitadel/pull/241) chore(deps): enable Renovate cargo manager and drop invalid uv manager

## Description

Fix `enabledManagers` in `renovate.json` so it passes validation and covers the Rust workspace. The org is moving vulnerability-fix PRs from Dependabot security updates to Renovate (vig-os/org-config#307), and Renovate only opens a vulnerability PR for a dependency that an enabled manager extracts.

## Type of Change

- [x] `chore` -- Maintenance task (deps, config, etc.)

## Changes Made

- `renovate.json`: `enabledManagers` goes from `["github-actions", "pep621", "uv", "npm"]` to `["github-actions", "cargo"]`.
  - `uv` is not a Renovate manager. It is missing from https://docs.renovatebot.com/modules/manager/ (Renovate handles `uv.lock` through `pep621`), and `renovate-config-validator --strict` rejects it: `The following managers configured in enabledManagers are not supported: "uv"`.
  - `pep621` and `npm` match nothing: there is no `pyproject.toml`, `package.json` or `uv.lock` on `dev` or `main`.
  - `cargo` is added, and the shared preset's weekly `lockFileMaintenance` now covers `Cargo.lock` too.
- `CHANGELOG.md`: entry under `## Unreleased` / `### Changed`.

**When it takes effect:** Renovate reads its config from the default branch, `main`. `main` still has the invalid list, so this change does nothing until the release train carries it to `main`.

## Changelog Entry

### Changed

- **Renovate manages the Rust dependencies**
  ([#240](https://github.com/vig-os/scitadel/issues/240)). `renovate.json`
  now enables `["github-actions", "cargo"]`, so Renovate opens update and
  vulnerability PRs for the Cargo workspace and its lock file maintenance
  covers `Cargo.lock`. The previous list named `uv`, which is not a Renovate
  manager and failed `renovate-config-validator --strict`, plus `pep621` and
  `npm`, which match no file in this repo. Renovate reads its config from
  `main`, so this takes effect with the next release.
