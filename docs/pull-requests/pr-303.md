# [PR 303](https://github.com/vig-os/scitadel/pull/303) fix(reader): the untrusted-content envelope reaches the render boundary

#287 — the release blocker. ADR-007 §1 requires an untrusted-content envelope for anything read out of a fetched or dropped-in document. #290 built the **type** and wired it into the write paths; it never reached the boundary this issue names.

The gap: `Paper.title: String` (`models/paper.rs:40`), and `"title": paper.title` going straight into `read_paper`'s JSON (`mcp/src/tools.rs:748`). A crafted PDF `/Title` or a landing page's `citation_title` was rendered as though scitadel had written it — into a terminal, into an agent's context, and into a log.

## The boundary is the type, not a call-site convention

`Paper.title` and `Paper.authors` are now `UntrustedText`. #287 asks for this explicitly: *"A type, not a convention... A doc comment saying 'be careful' is not a boundary."*

**37 files, and the count is the argument.** There was no judgement about which surface to wrap — the compiler enumerated them: ~10 real render paths moved to `rendered()`, ~20 test fixtures, and ~7 data paths that correctly stay on `as_str()`, each with a comment saying why (`papers.title`/`authors` columns, `bibtex`/`csl_json`/`csv_export` because *a truncated citation record is a corrupted citation record*, the manifest mirror, `bibtex_key`, `title_similarity` in dedup, the identity-check write).

Two consequences worth naming:

1. **A latent panic.** `&paper.title[..len().min(60)]` appeared at four call sites, byte-slicing a `String` — a panic waiting on a non-ASCII boundary. Replaced with `UntrustedText::preview(n)`, a rendering concern that belongs on the safe side.
2. **Two JSON forms, because one cannot guess.** `get_paper_tool` serialised the title raw via `serde_json::to_string_pretty`. That stays the *data* path; `Paper::to_display_json()` was added for display paths, and `get_paper`, `show` and `resolve_doi --json` moved onto it. Making `Serialize` emit the rendered form would have silently truncated every BibTeX and CSV export at 200 characters.

## The payload is extracted by the real extractors, not typed in

So the suite cannot pass on a fixture production would never produce:

- a PDF `/Title` in **UTF-16BE hex** — the form Word writes for a non-ASCII title, and the only `/Title` encoding that can hold a literal backslash;
- `citation_title` as **numeric entities** — the page's own decoder expands `&#x1b;` to a real ESC byte.

Both carry `ESC[31m` (colour), `ESC[2J` (erase display) and an OSC 8 hyperlink; both render as `Real Title click`. The test asserts the raw string still contains `ESC` **before** asserting the rendered form is neutral, so it cannot pass on a no-op.

One render test per boundary, in the crate that owns it — the TUI's rendered buffer in `views::reader`, and `read_paper`'s return.

**And I verified the invariant binds.** Reverting `Display` to `as_str()` makes exactly two tests fail, and both are the render tests. That is what makes "Display is the safe form" checked rather than commented.

`authors` is wrapped for a measured reason: `served_identity` reads it out of `citation_author` (`identity.rs:702`), and every metadata feed supplies it.

## What the ADR amendment records as deliberately not done

Appended as a dated amendment; history untouched. This is #287's fourth acceptance box, and it is the one that would otherwise rot:

- **The full-text envelope itself.** `full_text` and `r#abstract` are publisher-controlled and still unwrapped. `UntrustedText` caps at 200 characters, so wrapping the body would truncate a reader to nothing and turn a security fix into a different bug. An uncapped body neutraliser is a separate type with a separate cap.
- **Scripts and styles stripped.** Not implemented. `html_to_text` drops tags on the HTML path; the PDF path has no script content.
- **Prompt-injection framing.** The return does not tell the agent in prose that the body is fetched content it should not obey.

So: *every render path showing a publisher **title** is closed; every render path showing publisher **body text** is not, and it is blocked by that separate type.*

## A gap I found rather than closed

Provenance on `papers.title` read-back is **not recoverable from the schema**. A title stored from a document reads back labelled `Ours`, because nothing records which side of the boundary a stored title came from. Honest *today* — the NDJSON importer explicitly refuses to write a document's title into that column (`acquire_ndjson.rs:641`) — but a convention the schema does not enforce. The document's own claim is `resolved_title`, already labelled `PublisherSupplied`. A provenance column is a migration, and that is not this PR's to make.

Also worth a follow-up: `decode_pdf_literal` drops both bytes of a `\x` escape (`identity.rs:896`, `Some(_) => i += 2`), where the PDF spec says a backslash before an unrecognised character yields the character. A `/Title` ending `\)` therefore returns `None`. It is on the write side, I did not touch it, and the hex fixture routes around it.
