# [PR 285](https://github.com/vig-os/scitadel/pull/285) feat(acquire): identity checks, so no artefact is ever filed under the wrong work

S2c for #253. Delivers the criterion that matters most: **no artefact is ever filed under a mismatched identity** — a mis-filed full text is silently *wrong*, not merely missing.

`paper_identity_checks` existed in migration 013 with **no writer anywhere in the workspace** — the last such gap. There is now a writer that refuses to touch a human-overridden row, and a reader for the latest check.

## `ok` means corroborated, not merely unrefuted

A title match alone records `unverified`. `ok` needs positive corroboration — a year within ±1, or a first-author surname. The two are deliberately **asymmetric**:

- a first author is a property of the **work**, so it contradicts even at an exact title match (identical titles by different authors are two works);
- a year is a property of a **version**, so a 2021 preprint published in 2024 is one work, and a year never overturns a title that matches outright.

Thresholds were **calibrated against a measured table**, not guessed: ≥0.90 match, 0.70–0.90 tie, <0.70 mismatch.

The tie band exists because **the wrong answer scores higher than the right one**:

| case | score |
|---|---|
| a *different* work, `+ of the thyroid` | **0.885** |
| the *same* work, shorter served title | **0.853** |

A test asserts that no threshold can order those two — so only the ADR's tie-breakers can resolve them, which is why the year and author exist.

## `unverified` proceeds; `mismatch` does not

These look contradictory and are not:

- a **mismatch** is *positive evidence* the bytes are another work — the failure this exists to prevent;
- an **unverified** check is no evidence at all, and is a property of the *data* rather than of the fetch. A PDF with no `/Title` would return `unverified` forever, so blocking on it would mean **no machine run could ever acquire it**. The row is written either way, with both titles.

A consequence now stated in the ADR: **a PDF post-fetch check can only ever be `unverified` or `mismatch`**, because a PDF carries no year or author to corroborate its `/Title`. It still catches a redirect to another work.

## The criterion test

```rust
assert_eq!(report.acquired(), 0, "nothing was filed");
assert_eq!(fx.artefacts(), before,
    "#253: a mismatch must leave the artefacts table exactly as it found it");
assert_eq!(fx.count_blobs(), 0,
    "and no blob either — the bytes were discarded, not stored");
```

Row-for-row, not a count — and it also asserts both titles were recorded, since a row nobody can act on is not much of a record.

## Overrides are write-once, and re-queue the gap

`write_identity_check` refuses to touch an `overridden` row **and does not record its own score beside it**: a row whose status and timestamps disagree about who last touched it turns "newest row's status wins" into "newest row wins, whatever else it says". `phase_is_settled` then skips the phase entirely, so an overridden work is not blocked either — which is why `scitadel override-identity <paper> --reason "…"` also puts its want back to `pending`, since a settled work has nothing for `acquire` to pick up. That was a real bug found and fixed mid-slice.

`PreservedOverride` is a **normal outcome, not an error** — treating it as one would make a human decision look like a broken database. Machine paths cannot write `overridden` at all.

## OSTI, measured before it was written

Probed live; the observations are pasted into `osti.rs`:

- `purl/<id>` is 200 `application/pdf` with `%PDF-` magic — no API, no lookup;
- a **404 is a 265 kB HTML page**, not an empty body — so "the request succeeded" and "we got a document" are different questions, and the body decides. Content type is not consulted;
- a `purl` can redirect **off** `osti.gov`, which `PacedClient` follows with one permit per hop against *that* host's bucket.

Validated end-to-end: the served PDF's `/Title` and OSTI's records title normalise to similarity **1.0**.

`osti.gov` is left unrouted on purpose, taking ADR-007 §4's unknown-host defaults. The 5 s needs no attribution; the 500/24 h is our policy choice and is the number worth revisiting for a multi-lab campaign — my probe saw no 429 and no rate-limit headers, which is an observation, not a published limit.

## ADR-007 §3 amended

Three of these change what "a mismatch blocks filing" means operationally, so they belong in the decision record rather than only in code: `ok` requiring corroboration, `unverified` not blocking, and the write-once override that re-queues the gap. Plus the one addition to §1's vocabulary — `source = 'human'` — because reusing a machine spelling would make a person's ruling look like OpenAlex had said so.

## Honest limitations

- **`pmcid`/`osti_id` are not on the `Paper` model.** ADR-007 §1 line 236 says they joined it in S1; they did not. `Paper` is written back wholesale by `save()`, so a `Paper` carrying `osti_id: None` for a work that *has* one would silently null the column. Hence single-column `set_osti_id`, tested against exactly that hazard.
- **`correct_doi` exists and is tested but has no production caller** — S3's resolve-then-rank is its intended one. It is there so the `doi_corrected_from` recording cannot be forgotten when it lands.
- **Crossref and DataCite are declared as identity sources but unreachable** — no adapters yet (S3). Pre-fetch checks run off OpenAlex alone.
- **The matcher's thresholds are calibrated on reasoned-about pairs, not on the raid corpus.** Before this is trusted over 587 DOIs, run `acquire --dry-run` then the pre-fetch check over the corpus and count `mismatch` + `unverified`. If `unverified` dominates, the strict corroboration rule is too tight for this data and should be revisited *before* the numbers harden into the ADR.
- **`RouteId::Osti.artefact_version()` is `unknown`**, so an OSTI result is filed as an unknown-version full text and a `vor` want reports `wrong_version`. Correct-by-default, but the route cannot yet *close* a want.

## Not in this PR

The remaining `acquisition_attempts` outcomes (`too_large`, `bad_magic`, `login_redirect`, `http_error`) still have no writer — a fetch failing on a size cap is recorded as a bare `error`. That should land before `gc` and the manifest mirror claim a complete audit trail. Then: `scan`/`attach`, manifest mirror, `gc`, `acquire --from works.ndjson`, and the TUI move onto artefacts. **#253 stays open.**
