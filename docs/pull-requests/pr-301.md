# [PR 301](https://github.com/vig-os/scitadel/pull/301) feat(db): record the licence the artefact was accepted under, and audit the columns

#291. The manifest mirror has been reporting `null` for the licence of every artefact since migration 013 — `manifest.rs:214` emits `license_url`, and nothing in the workspace has ever written it. Because nothing wrote it, that `null` was indistinguishable from "we looked and there is no licence": #261's overclaim, in a mirror.

The reason nothing wrote it is not oversight. **The resolve pass throws the licence away.** `registry.rs:420`'s `LicenceOffer` carries Crossref's `license[]` with `content-version`, `start` and `delay-in-days` — exactly the four columns migration 013 declares — and `Candidate` kept only the derived `LicenceStrength`. So the artefact recorded a *classification* (`access_basis`, from the route) but not *which grant*, the part a reader or downstream tool needs.

#291's rule — don't add writers speculatively — is now satisfied for these four columns, because the values exist. This threads the offer through rather than adding fields.

## The offer rides the chosen candidate, and covers only its own version

A licence offer is a statement about a *work* made by a registry, and it applies to the document the chosen candidate serves. So it is attached to the candidate and survives only when a grant was in force **for that candidate's own version** — a `vor`-only CC-BY never reaches a preprint candidate, and the five derived routes never consult the work-level offers at all. The winning offer is taken only when the candidate's strength is `OpenLicence`.

Verified by `the_licence_offer_rides_the_version_it_covers_and_no_other`: a Crossref record with a `vor`-only grant and two `link[]` candidates gives the VoR one the offer, the preprint one `None`, and the chosen VoR candidate is what carries it into the row. `the_licence_the_chosen_candidate_carried_reaches_the_artefact_row` pins it end-to-end through wiremock. A re-download through a source naming no licence **removes** the grant rather than leaving a stale one.

This is *under*-attribution, deliberately: deriving a licence from any source's offer would file a CC-BY grant against an artefact a subscription-only route served.

## The manifest no longer presents silence as a known value

The four licence fields get `skip_serializing_if`. `tdm_policy_ref`, `auth_context`, `retain_until` and `derived_from` were never emitted at all — `ManifestArtefact` has no field for them — so the **licence columns were the whole exposure, not the eight #291 names**.

## Migration 013's columns are now audited, in both directions

`crates/scitadel-db/tests/013_column_writers.rs` reads each table's columns from the **live schema** (`PRAGMA table_info`, so later migrations count) and each write surface from the **write structs' public fields**. That is the artefact trap #291 names: `write_artefacts_in` builds its column list as a runtime `{columns}` variable, so a regex over the SQL produced 20 false positives in the first sweep. `Statement` readers take only the `SET` side of an `UPDATE` — `override_identity`'s statement ends `WHERE id = ?4`, and a naive line-reader reported `id` as written.

**Verified by experiment, both directions.** Adding `embargo_until TEXT` to the migration fails the build with:

```
artefacts.embargo_until: no writer fills it and no allowlist entry names it.
Either the writer for it has arrived (add the field to the write struct, or
add the column to the statement), or it belongs to a later slice (add an
UNWRITTEN entry with the issue that owns it).
```

and the allowlist is checked for entries whose column no longer exists *and* for entries a writer now fills. A second test asserts the created-table list equals the audited list, so a new table cannot pass vacuously.

## `derived_from` keeps its owner, and it is not #257

Migration 013's own `license_url` comment says derived artefacts copy these from `derived_from`; #234's manifest shape puts `derived_from` on `table` and `figure` entries; #234 §3 says tables come from JATS `<table-wrap>`. So it is provenance for derived artefacts, unwritten because no extractor exists. **The owner is #254** (ADR-007's slice table carries "JATS tables → structured JSON", with "the number of JATS `table-wrap` elements equals the number of table artefacts") — not #257 S5, which is SI discovery and names no extractor. Documented in the migration; the dated ADR copy is untouched.

## Two gaps this found that #291 missed

- **`papers.pmcid` has no writer at all**, and `write_osti_id` names it for its sibling column. Allowlisted against #254, whose metadata pass is the intended producer.
- **`tdm_authorisations` has no writer for *any* column, including `publisher`** — #291 said `publisher` was written. The whole table is allowlisted against #258, per #291's own rule that a column arrives with the slice that has values for it. The substrate is #258's to build.

## Left out

`tdm_policy_ref`, `auth_context`, `retain_until` stay unwritten against #258. No change to `ManifestArtefact`'s other optional fields (`publisher`, `label`, `caption`, `source_url`, `imported_from`) — they also emit `null`, but their absence is not a claim about the world and they are not this issue's scope.
