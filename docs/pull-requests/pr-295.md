# [PR 295](https://github.com/vig-os/scitadel/pull/295) feat(acquire): Europe PMC and the PMC-OA dataset as OA candidate sources

Wave 3 of #254 — ADR-007 §3 steps 1–2. Neither service existed: `Registry` had no variant for either, so **both contributed zero candidates**, and `RouteId::EuropePmc`/`RouteId::PmcOa` were dead. Verified by grep before writing a line.

## The PMC-OA Web Service does not exist

ADR-007 and `route.rs` both describe `oa.fcgi`. Measured 2026-10-07 (I re-verified all of this myself):

```
GET .../pmc/utils/oa/oa.fcgi?id=PMC7759461  -> 404   (all three hosts)
GET .../pmc/tools/oa-service/               -> 200, "no longer available"
```

`pmc-oa-opendata` is an **S3 bucket name**; the whole API is anonymous S3 REST — a `ListObjectsV2` prefix listing plus one JSON per version. Consequences the spec didn't mention: **no DOI lookup** (the bucket is keyed on PMCID alone), and the per-version `pdf_url` is an `s3://` URI with an `?md5=` digest that reqwest cannot fetch and `is_fetchable_url` correctly refuses. Rebased onto the HTTPS form, which answers 200 with a matching ETag.

`route.rs:148` says `oa.fcgi` was "retired on 2026-08-25". The *page* says that date; the service 404s. If it had been probed on the day, the comment would read differently.

## A third party's JSON must not name our host

My first cut of the `s3://` rewrite used the **bucket name from the JSON**, so the dataset chose the authority we then fetched from. `object_url` now rebases the *key* onto the adapter's configured base and `MetadataBases::allows` refuses the foreign host.

This is #292's bug class — a request that escapes to an authority nobody asserted and passes because no fixture existed — caught while writing the test that exists to catch it.

## `TDM` is not a licence

The bucket marks author manuscripts `license_code: "TDM"`: text-mining permission, otherwise fair use. That is **not a reuse grant**, so it maps to `FreeToRead` and never to `OpenLicence`. Filing it as open would have coverage report a reusable full text we have no right to reuse.

## Version evidence: a repository's claim beats an index's

`VersionSource::Repository` is a new variant, consulted **before** the location-word table. `version_from_location_word`'s contract is that its input is "the same three words in both indexes, **measured**". `is_manuscript` and `epmcAuthMan` are not a fourth word in that vocabulary — they are booleans about one stored copy, in two field names, from two services that share no schema. Widening the table would leave the comparator looking at three-sources-agree spelling for a claim one source made.

`Rank`'s two fields and derived `Ord` stay untouched, so wave 2's `ranked_order_is_documented_and_pinned` still pins the same claim.

## I fabricated a quotation from the ADR in wave 2

`METADATA_BUCKETS` carried:

> ADR-007 §3 lists them: "It may hit OpenAlex, Crossref, DataCite, Unpaywall."

**That sentence is not in the ADR.** §3 names **five** sources for the resolve pass, and the fifth is Europe PMC — with the very fields this slice reads. So the invented quote didn't just fail to cite; it quietly reduced a five-source requirement to four **and excluded §3 step 1's own subject**, which is how a plan asserted four buckets and called it the ADR.

That is exactly the failure mode this codebase has an issue for (#261's overclaim rule), committed by me in a doc comment, as a direct quotation. The comment now quotes the real list — and because the `pmc-oa-opendata` bucket genuinely is *not* in that list, it **argues** for adding it instead of citing it.

## Europe PMC's three manuscript flags are independent

`authMan` / `epmcAuthMan` / `nihAuthMan` are three booleans, not one notion. Collapsing them files a `PPR` preprint as `am` — above the preprint rung, inverting ADR-007 §3's own ladder. Each honoured alone, ordered manuscript > `source: PPR` > unstated.

And a `MED` record with every flag `N` is **not** a version of record: Europe PMC does not assert its copy of a MEDLINE record is the typeset article. So `Unstated` — a rung, ranked and reported.

Also measured: `resultType=core` is load-bearing (`lite` carries no `fullTextUrlList`, no `license`, no flags); `license` is a short **code**, not a URL.

## Landing pages are now OA-gated

Step 6 was a blanket last resort — a publisher landing page was fetched for any work, OA or not. ADR-007 §3 step 6 says "for OA works only". **Four pre-existing tests were passing *because* of the blanket behaviour**; they now assert the gate.

## Known limitation — reported, not papered over

```
europepmc.org/articles/PMC7759461?pdf=render   -> 403  (Cloudflare, every UA/Accept tried)
ebi.ac.uk/.../fullTextXML                     -> 200
```

A Europe PMC candidate may be named and then record `Inconclusive` on fetch. I did **not** substitute the JATS endpoint — that files XML where the plan says PDF, a different artefact, and belongs with #288's SI work. Filed separately.

1028 tests across 27 suites, up from 991 (+37). `fmt --check` clean. Clippy `-D warnings` clean on pinned 1.98.1. Live-probe claims for the 404/403/S3-200 all re-run independently before merge.
