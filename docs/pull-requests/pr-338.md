# [PR 338](https://github.com/vig-os/scitadel/pull/338) fix(reader): cap build_annotated_paper and scroll the TUI reader

Closes #307.

#306 built the `UntrustedBody` envelope and wired `Paper.r#abstract` + `Paper.full_text` through it, finding two uncapped body render paths it recorded but did not fix. Neither was a security fault (the envelope neutralises on the way out); both were rendering-quality bugs. This PR resolves both.

## Problem

1. **`build_annotated_paper` returned the whole `full_text`.** `read_paper` has a 20_000-char `max_chars` cap; this sibling returned the raw whole-body column, so an agent calling the annotated variant got a different — and much larger — document than the plain one, by accident rather than by design. It was also a silent-drop risk for annotations past any paging an agent did downstream.
2. **The TUI reader had no scroll offset.** A 40 kB body was rendered into one `Paragraph` sized to the terminal, so only the top of the document was reachable — including every match or highlight below the fold.

## Fix

### MCP: `build_annotated_paper` honours `max_chars` / `offset`

- New `max_chars` (default `20_000`, the same as `read_paper`) and `offset` (default `0`) parameters.
- Response carries `truncated`, `total_chars`, `offset`, `next_offset` (`null` at EOF) so a caller can page through a long paper deterministically.
- `annotations_outside_window` + `annotations_outside_window_anchors` surface every anchor whose `char_range` falls outside the returned window, so a paging agent never silently loses a comment.
- Body slicing is char-aware, matching `read_paper`'s own slice; multi-byte glyphs never halve across the cap.
- Envelope intact: the body goes out through `UntrustedBody::rendered()` (the security half — escapes, control, invisible chars go). The abstract stays whole; it is short, and a truncated abstract is a corrupted citation record.

### TUI reader: scroll offset + auto-follow highlights

- Added `reader_scroll: u16` to `Overlay::PaperDetail`.
- Keys: `j`/`k`/`Down`/`Up` (one row), `d`/`u`/`PageDown`/`PageUp` (half page = 10 rows, matching the single-pane detail scroll's convention), `g` (top), `G` (bottom).
- `Shift+J` / `Shift+K` keep their `#97` highlight-hop semantics AND now auto-scroll onto the hopped highlight's line, so a match below the fold is reachable. The pre-existing `Up`/`Down` highlight-hop alias is gone — those keys now scroll, which is the convention everywhere else in the TUI. `J`/`K` remain the hop shortcut.
- Scroll is a pure ratatui `Paragraph::scroll` offset, so the highlight positions `build_highlights` computes from `char_range` land on the same row they came from — a scroll never desyncs from `root_at`.
- Clamping happens in `draw_text_pane`, where the body's line count is cheap, so a stale offset (including `G`'s `u16::MAX` sentinel) cannot blank the pane. Closing the reader (`R`/`q`/`Esc`) resets the offset.
