# [PR 284](https://github.com/vig-os/scitadel/pull/284) feat(acquire): the acquire command, gated on derived "have" so a re-run is silent

Part 2 of slice S2 for #253. Closes the blocker PR #283 found, and delivers `acquire` itself.

## First: two columns that had no writer

`acquisition_state.publisher` and `next_attempt_at` were unreachable from the whole workspace — no field on `StateWrite`, absent from the INSERT. So ADR-007 §2's *"`rate_limited` — retry at `next_attempt_at`"* had nothing to read, and `--resume` could not mean anything. PR #283 flagged this as blocking this slice; it is fixed here, **including in the `ON CONFLICT` guard** — a row whose only change is a moved `next_attempt_at` would otherwise silently not update, which is the shape an idempotence bug takes.

`StateRow` also gained a round-trip to the `StateWrite` that reproduces it, so a read-modify-write cannot drop a column the report reads.

## A re-run puts nothing on the wire

The criterion is not "idempotent" in the row-count sense. It is that the second run must not even *ask* a publisher:

```rust
let after_first = fx.request_count().await;
assert!(after_first > 0, "the first run did fetch something");
// … second run …
assert_eq!(fx.request_count().await, after_first,
           "the second run put nothing on the wire");
```

The count is compared **across** the second run rather than against zero, and the test asserts the first run *did* fetch — so "zero" is a measurement, not a fixture that never ran.

Satisfaction is decided from `coverage.rs`'s derived "have" before any I/O, reusing its `wanted_version` rules and its `missing_on_disk = 0` clause rather than writing a second derivation. A held want is never planned for work at all.

`--dry-run` is checked as **whole-table equality** across `acquisition_state`, `artefacts`, and the three legacy `papers` columns — a count would miss an in-place update.

## Statuses are only written when established

`LegOutcome` from #260 is reused unchanged:

- an index answering 200 and naming no OA location **never** yields `unavailable`
- an unclassified publisher prefix records `None` plus `RouteVerdict`'s note, never a guess
- `publisher_note` prints only when `publisher` is `NULL`, so a classified publisher gets no stray "no route" line

## Seven tests, one per requirement

`a_second_run_makes_no_network_calls_for_held_artefacts` · `dry_run_writes_nothing_and_calls_nothing` · `resume_defers_a_rate_limited_work_until_next_attempt_at` (future → no request, past → runs; the test that proves the blocker fix was needed) · `acquire_is_idempotent` · `an_unclassified_publisher_records_no_publisher_and_no_route_verdict` · `an_index_naming_no_location_never_yields_unavailable` · MCP `acquire_queue_add` enqueues ids and `acquire` drains only those.

## One placement decision

`acquire` lives in `scitadel-adapters` beside the existing ladder, not in a new `scitadel-acquire` crate. ADR-007 §3 wants the latter, but moving a cohesive unit later is cheap and inventing a half-populated crate now is not.

## A tape I wrote and did not ship

`acquire` is user-visible, so I tried to tape `acquire --dry-run` — it makes no network calls and no writes, so the frame is deterministic. The tape types and executes cleanly and vhs reports the `Screenshot` step, but **produces no PNG on this machine across three attempts** (two seed sizes, longer waits). Rather than ship a tape I could not verify, I marked the change exempt and explained why.

The command's output is already pinned by unit tests asserting request count and whole-table equality, so the tape would have added a rendered frame rather than a behavioural claim. The sibling reporting command from #283 is covered by `tests/vhs/cli-coverage-action-list.tape`, which exercises the same derived "have" this plan is gated on. **Whether vhs is failing to write PNGs for new snapshot directories here is unresolved and worth a look.**

## Not in this PR

`scan`/`attach`, the manifest mirror, `gc`, `acquire --from works.ndjson`, pre/post-fetch identity checks, the OSTI route, and moving the TUI and `read_paper` onto artefacts. **#253 stays open.**
