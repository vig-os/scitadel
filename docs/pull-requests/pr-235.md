# [PR 235](https://github.com/vig-os/scitadel/pull/235) fix(build): pin rust toolchain in rust-toolchain.toml for local + CI

## Summary

Fixes #229 — `just lint` in a fresh `nix develop` failed with
`unknown lint: clippy::unused_async_trait_impl` because the flake shipped
clippy 1.95 while CI's `dtolnay/rust-toolchain@stable` was on 1.98. This
adopts issue option 2, the durable fix: one `rust-toolchain.toml` at the repo
root is the source of truth for the Rust channel, resolved identically by
`nix develop`, `nix build .#default`, and every repo-owned workflow.

## What changed

- **`rust-toolchain.toml`** — pins `channel = "1.98.1"`, profile `minimal`,
  components clippy, rustfmt, rust-src, rust-analyzer.
- **`flake.nix`** — `rustToolchain` now built via
  `rust-bin.fromRustupToolchainFile ./rust-toolchain.toml`; both the dev shell
  and `packages.default` share it.
- **`flake.lock`** — `rust-overlay` bumped so its manifest set knows 1.98.1
  (`nix flake update rust-overlay`; nixpkgs untouched — nothing else
  relocks).
- **CI workflows** (all repo-owned, none devkit-managed): `rust-ci.yml`,
  `vhs.yml`, `binaries.yml`, `publish-crates.yml`, `release-extension.yml`,
  `prepare-release-extension.yml` — every `dtolnay/rust-toolchain@stable`
  step is replaced by the runner image's pre-installed rustup:

      - name: Install pinned Rust toolchain (from rust-toolchain.toml)
        run: rustup show active-toolchain || rustup toolchain install

  `rustup show active-toolchain` reads `rust-toolchain.toml` and installs
  the pinned channel + components on the first run (subsequent runs skip
  because it prints the resolved override), which is the single-source-of-
  truth path — no version is hardcoded in any workflow. `binaries.yml`
  keeps its per-matrix cross target: `rustup target add "${{ matrix.target
  }}"` attaches x86_64-apple-darwin to the pinned rustc for the
  macos-latest (Apple Silicon) cross build. `rustup show active-toolchain
  && rustc --version` follows every setup so drift is visible in the job
  log.

  (An earlier attempt on this branch used `dtolnay/rust-toolchain@master`
  hoping it would auto-detect the file; it does not — that feature belongs
  to `actions-rust-lang/setup-rust-toolchain`, not to dtolnay's — and the
  first CI run failed with `'toolchain' is a required input`. The second
  commit on this branch is the fix.)
- **`README.md`** and **`docs/RELEASING.md`** document the pin and the
  deliberate bump procedure (edit one line, `nix flake update rust-overlay`,
  land in a dedicated PR).

## Notes

- Devkit-managed workflows are left alone (Scaffold Drift gate would fail);
  they either reuse repo-owned workflows for Rust steps or provision no Rust
  toolchain at all.
- Renovate's enabled managers do not touch this file by design — toolchain
  bumps stay deliberate, matching the repo's precedent for `vigos` and
  `nixpkgs` pins.
