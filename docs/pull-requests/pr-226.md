# [PR 226](https://github.com/vig-os/scitadel/pull/226) chore(repo): upgrade devkit scaffold 1.6.0 -> 1.17.0

## Description

Upgrades the vigOS devkit scaffold from **1.6.0** to **1.17.0** (released
2026-09-28), and moves the pinned `vigos` flake input in lockstep. No breaking
change in that range affects this repo — the one `Breaking` entry (devkit#1421)
removes the `devc-upgrade` recipe, a devcontainer-mode convenience this
`direnv`-mode repo never used.

## Type of Change

- [x] `chore` -- Maintenance task (deps, config, etc.)

### Modifiers

- [ ] Breaking change (`!`)

## Changes Made

Three commits, separated so the mechanical diff stays reviewable:

**`3984166` — scaffold regeneration.** Adds `abandon-release.yml` (rejects a
finalized but still-draft release), `prepare-hotfix.yml` (cuts a patch from
`main` without carrying what `dev` accumulated) and `.github/actionlint.yaml`.
Retires the `renovate-changelog` build/commit pair, superseded upstream by
release-time changelog synthesis. `.vig-os` gains the knobs added since 1.6.0:
`DEVKIT_LANGUAGES=rust` (seeded from `Cargo.toml` detection) and
`DEVKIT_LICENSE=none` (this workspace is `MIT OR Apache-2.0` with its own
`LICENSE-MIT`/`LICENSE-APACHE`, so devkit should not manage an Apache-only
`LICENSE`). Every other new knob keeps its default — the rendered commit,
branch and refs type sets already matched the stock ones.

**`35c2d10` — toolchain and hook reconciliation.**

- **`vigos` flake input 1.6.0 → 1.17.0.** `flake.nix` is a preserved file the
  scaffold cannot bump, and it supplies `vig-utils` (the release train's
  changelog scripts) and `pymarkdown`. The installer warns about exactly this:
  left behind, CI would run the 1.6.0 toolchain against the 1.17.0 scaffold.
- **`shellcheck` folded onto `language: system`.** The `shellcheck-py` wheel
  cannot be built under Python 3.14, which the relocked toolchain provides, so
  the hook could no longer install at all. `shellcheck` and `actionlint` are now
  declared in the dev shell: this repo owns its flake rather than deriving it
  from `mkProjectShell`, so the binaries the newly inserted `actionlint` and
  `shellcheck-composite-actions` hooks need have to be declared here.
- **Five `SC2001` suppressions in `vhs.yml`**, now reachable through
  actionlint's bundled shellcheck pass. Each is `echo "$var" | sed 's/^/  /'`,
  which indents *every* line of a multi-line value; `${var//search/replace}` has
  no per-line anchor and cannot express it, so the suggestion does not apply.
- **Four orphaned scaffold paths removed** — `.cursor/` (superseded by
  `.claude/` in 0.4.0), `.hadolint.yaml` (0.4.0),
  `.github/actions/resolve-image/` (1.1.0) and `renovate-changelog.yml` (0.3.5).
  Devkit prunes a retired path only when the tree predates the release that
  retired it, so at a 1.6.0 pin all four sat past its reach and would have
  ridden along indefinitely. `scripts/check-skill-names.sh` had its default scan
  path repointed from `.cursor/skills` to `.claude/skills`.

**`70bbf73`** — the changelog entry.

## Additional Notes

**`devkit-upgrade.yml` could not perform this bump.** The legacy
`DEVKIT_UPGRADE_APP_ID` org secret is scoped to four repos and this is not one;
the 1.6.0 workflow reads only that key, while 1.17.0 reads
`DEVKIT_UPGRADE_APP_CLIENT_ID` (which *is* granted here). The repo could not
upgrade itself to the version that fixes its own upgrade path, so this went
through `install.sh --force`. Widening the deprecated secret's scope was
rejected as the fix since devkit is removing it (devkit#1366). **Future bumps
can use the workflow.** This likely resolves part (a) of #209.

Please confirm **`Scaffold Drift`** is green — it re-runs the pinned scaffold and
is the best single proof the regeneration was complete.

Follow-ups opened from this upgrade, all deliberately kept out of this PR:

- **#227** — require the devkit `ci.yml` checks (`CI Summary`, `Scaffold Drift`,
  `Commit Messages`) in the `main`/`dev` rulesets. None of them gate merges
  today, so scaffold drift can land silently. Changes merge gating, so it is its
  own decision.
- **#228** — adopt the five devkit governance hooks this repo never folded in
  (`validate-commit-msg`, `check-agent-identity`,
  `prepare-commit-msg-strip-trailers`, `nixfmt`, `just-fmt`) and activate
  `core.hooksPath`. Notably, the commit/branch-type knobs this PR renders have no
  local hook driving them, and the no-AI-attribution rule is not hook-enforced
  here despite the workspace docs saying it is.
- **#229** — the pre-existing `just lint` failure (local nix rustc 1.95 vs an
  `#[allow]` for a clippy 1.98 lint). Unrelated to this PR and proven so; fixing
  it means moving the Rust pin.

Also worth noting: this bump likely resolves **part (a) of #209** — the scaffold
now mints its App tokens from `*_CLIENT_ID`, so the numeric `COMMIT_APP_ID` /
`DEVKIT_UPGRADE_APP_ID` surfaces that issue tracked are gone from the managed
workflows. Worth re-reading #209 to see whether part (b) is also obsolete after
the move to crates.io trusted publishing (#224).
