# [PR 270](https://github.com/vig-os/scitadel/pull/270) ci: drop the contract-tests job that could never fire

Replaces #267, which was opened against a branch named `ci/239-…`. `ci` is not an accepted branch type here (the allowed set is `feature,bugfix,hotfix,release,docs,test,refactor`, plus bare `chore/`), so the branch-name check rejected it. Renamed to `test/`, since a CI workflow that runs the test suite is test infrastructure.

## Problem

The `contract-tests` job in `.github/workflows/rust-ci.yml` is guarded on `github.event_name == 'schedule'`, but the workflow declares only `push` and `pull_request`. It is skipped on every run, so `cargo test --features contract-tests` is exercised nowhere in CI.

## Adding a `schedule:` would not have helped

The `contract-tests` feature is declared in `crates/scitadel-adapters/Cargo.toml` as an empty `contract-tests = []`, and **nothing in the tree is gated behind it**. Measured:

```
cargo test --workspace                           -> 552 tests
cargo test --workspace --features contract-tests  -> 552 tests
```

Identical. Both the job and the feature were introduced empty in the initial Rust rewrite (`d413773`) and never gained content — DES-002 lists them as planned deliverable E4, which is still unimplemented.

So the job is **removed rather than scheduled**, along with the empty feature that made it look meaningful. Scheduling it would have produced a weekly green tick and zero additional coverage.

## Audit of the other workflows

Checked every `github.event_name ==` guard against its workflow's `on:` block:

| Workflow | Guard | Trigger declared | Reachable |
|---|---|---|---|
| `ci.yml` | `pull_request` | `pull_request` | yes |
| `publish-crates.yml` | `pull_request` | `pull_request` | yes |
| `vhs.yml` | `pull_request` | `pull_request` | yes |
| `rust-ci.yml` | `schedule` | — | **no** |

This was the only dead guard in the repo.

## Verification

- Workflow still parses as valid YAML with `jobs: ['lint', 'test']` and `triggers: ['push', 'pull_request']`.
- `yamllint -c .yamllint` clean.
- `cargo build --workspace` and the full test suite (23 binaries) green.
