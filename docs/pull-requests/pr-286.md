# [PR 286](https://github.com/vig-os/scitadel/pull/286) feat(acquire): leases, the manifest mirror, scan/attach, gc, and NDJSON import

S2d for #253 — the rest of S2's CLI surface, plus the lease primitive the manifest depends on. **This closes the last of #253's four acceptance criteria** (raid's NDJSON import).

Three more migration-013 tables turn out to have had **no writer at all**: `acquisition_leases` here, and `acquisition_attempts.outcome`'s `bad_magic` and `too_large`, which had a vocabulary but nothing that could produce them. That is now the third slice in a row to open this way — worth a sweep for the remaining unwritten tables.

## gc: the window no lock can close

The interesting part, because a blob may be the only copy of a file somebody spent an afternoon getting.

`store_blob` writes the file **outside** the transaction, so an in-flight fetch's staged file has no `blobs` row and gc cannot see it. Worse, `store_blob` short-circuits when the destination exists (content-addressed — same digest, same bytes), so a fetch of an already-stored digest writes **no file** and only then commits its reference. If gc's transaction commits in that window it removes both row and file, and the fetch lands an artefact pointing at nothing.

No lock closes this. A **24 h grace period** does — any fetch that could still reference a blob started before gc ran. It is a floor, not a default, and `--min-age-hours` only widens it.

Deletion is additionally scoped by digest — relative, no `..`, under `blobs/`, in its own two-hex shard, named `<digest>[.ext]` — so **no directory walk feeds the delete list** and a hostile `rel_path` cannot aim gc outside the store. The delete re-runs the same `NOT EXISTS` guard inside `BEGIN IMMEDIATE`, row then file, so a failed unlink leaves an orphan *file*, which is the safe direction.

## The measured 7-of-27 case

ADR-007: *7 of 27 "SI" files on disk were HTML landing pages*. `magic.rs` compares the *claim* (the extension) against the *evidence* (a bounded 8 KiB head — never the whole 250 MB file), and **an HTML page is refused under every non-HTML declared format**, because a table alone would let it through since SI is unbounded.

Refusal needs *positive* evidence: unrecognised content is `Unknown`, not a refusal — unrecognised is not evidence, the same reasoning `identity`'s `Unverified` rests on.

The size cap is keyed on **kind**, not format, so a big workbook cannot be filed as a figure to get under a smaller cap.

## Leases: the boundary is the test

`WHERE lease_until_ms < ?4` is strictly less-than, so a lease is live for `[now, until]`. `now = until` still refuses and `now = until + 1` takes over — asserted, so a `<=` "fix" cannot pass. Renewal and release are both scoped `paper_id AND owner`, so a process that lost a work **learns** it lost the work; otherwise a lease degrades into a suggestion.

## The manifest is a mirror, never an input

`the_manifest_is_never_read_as_input` compares three libraries differing only in whether the mirror is absent, correct, or **lying** — it claims three forged artefacts, zero gaps and a different paper — and every DB-derived answer must be identical. Reading it and deleting it both change nothing. Written after the DB commit, by the lease holder only, via rename.

## raid's NDJSON, with its curation statuses intact

No schema or fixture in this repo pins raid's `p1`/`p3` field names, so every reading is documented in the module header *and reported by the command*, and unread keys land in `unknown_fields` so "without loss" is checkable from one report.

"Curation statuses stay raid's" has a precise reading, forced by the CHECK constraint:

- a raid status that **is** one of §2's passes through verbatim (case-insensitively — a queue from a spreadsheet is not a schema);
- anything else becomes `pending`, a claim about **scitadel** ("never tried by us"), with raid's verdict preserved **character-for-character** in `reason`.

Never renamed into a scitadel word that reads like raid's meaning, and never dropped, which would lose the gap entirely.

Identity expectations from a foreign file are **reported with both titles, never applied** — the pre-fetch check reads the stored row, and overwriting it from a foreign file is exactly the guess #260 and #261 exist to stop.

## Three bugs the tests caught

`attach` hard-coded `Slot::FullText`, so `--kind si` got `access_status = 'full_text'` and skipped the identity check entirely. `attach` leaked a five-minute lease on every early-return path. And `--json` exited 0 on a refusal — a script checking only the exit code would have read the 7-of-27 failure as a success.

## What I would treat as blocking for a release

- **`read_paper` has no untrusted-content envelope.** ADR-007 §1 requires it and nothing here touches it. A PDF's `/Title` and a page's `citation_title` are attacker-controlled text heading for a reader — and `scan`/`attach` are new ways for arbitrary bytes to enter the library. This is the one item from this slice I would not ship around.
- **`too_large` is enforced only on local files.** `download.rs` still has no size cap on a fetched body, so an HTTP route can write a 2 GB blob today. Same fix, different call site.
- **The legacy dual-write is still on** (`record_download` still writes `papers.local_path`; `find_cached_file`/`read_paper`/the TUI still read it). That is S2e, and it is now unblocked.

Also worth a decision rather than inheriting: whether `acquisition_leases` should be pruned. Rows are reused on takeover, so a work fetched once keeps one row forever — harmless at this size, and `gc` deliberately does not touch lease rows.
