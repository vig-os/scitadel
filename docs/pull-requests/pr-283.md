# [PR 283](https://github.com/vig-os/scitadel/pull/283) feat(db,cli): coverage and action_list, with derived "have" and one shared report

Part 1 of slice S2 for #253: **the reporting layer**. `acquire` itself and the rest of the slice are not in this PR — see "Not here".

## Why this is the piece the acceptance criteria are stated against

Across #261, #260 and #275 the same defect kept recurring in different clothes: **the report said something the system had not established.**

- 249 papers were told "no TDM route available" for publishers nobody classified.
- Three free bioRxiv preprints were reported unreachable because an index field was null.
- A DOI-resolution crawl hid behind a bucket *named* `doi.org` while carrying the unknown-host *policy*.

So a command whose job is to report has to be structurally incapable of overstating.

## `action_list` totals == `coverage` totals, by construction

> The `action_list` counts must equal the `coverage` missing totals.

Two independent queries would agree today and diverge the first time one is edited. Instead there is **one read**:

- `coverage_report` builds a `CoverageReport` from a single pass over `acquisition_state`
- `ActionList::from_report` **consumes** its entries, pushing each into exactly one bucket
- `accounted()` is a sum over that *partition*, not a second count of the list
- both CLI commands render projections of that same value — `coverage` renders `list.coverage(kind)`, `action_list` renders the groups — and the headline `N` is identical in both

The test parses `N` back out of both renderings, and runs against a mixed corpus with entries in **both** buckets (so it cannot pass by accident).

## "Have" is derived, never stored

`acquisition_state` records only what is *wanted*; what is *held* is derived from `artefacts` on every read, so the two cannot drift apart.

`vor` accepts `vor`, plus `unknown` **only** on rows from `legacy`/`import_flat` (those predate version tracking). `any` accepts everything. `am` accepts only `am`. An unrecognised `wanted_version` satisfies **nothing** — so unknown input can never read as `any`.

One clause the ADR does not state, added because it is the same species of bug: the held query also requires `missing_on_disk = 0`. That column means "path recorded, no usable bytes" — without the clause, a deleted file reports as a held full text.

## The report cannot overstate

- Unclassified publisher → **no** publisher name, **no** TDM verdict; `RouteVerdict::note()`'s wording, which exists for exactly this.
- TDM-capable publisher whose status is neither `tdm_available` nor `tdm_key_missing` → **no** verdict, because re-reading the keychain from a reporting command would prompt for an unlock.
- Every ADR status appears even at count zero, so "no such papers" ≠ "not tracked".
- `pending` is not in the human list (§2 marks it "—"), and the report says where it went.

Three of the implementer's own tests caught this class during the work — a `GroupKey` whose derived `PartialEq` included the DOI (splitting one publisher into N groups), an insert that ran unconditionally, and zero-count placeholder buckets.

## Blocker found for the rest of S2

**`acquisition_state.publisher` and `next_attempt_at` have no writer anywhere in the workspace** — `StateWrite` has no field for either and the INSERT omits both. So:

- **`acquire --resume` cannot honour §2's "`rate_limited` — retry at `next_attempt_at`."** Nothing can record that time, so the next slice has nothing to read. `StateWrite` needs both fields **before** `acquire` is written, not after.
- The report derives the publisher from the DOI registry instead (the better source), but the column should be filled or documented as derived-only.

Also noted: `has_fulltext_artefact` ignores `access_status` and `version`. Correct for its documented purpose ("do we hold *a* full text file?"), but it is **not** §1's "have" and must not be reused as one.

## Not here

`acquire` (idempotent, `--dry-run`, `--resume`), pre/post-fetch identity checks, the OSTI route, `scan`/`attach`, the manifest mirror, `gc`, `acquire --from works.ndjson`, and moving the TUI and `read_paper` onto artefacts.
