# [PR 312](https://github.com/vig-os/scitadel/pull/312) fix(adapters): point patentsview at a live PatentSearch endpoint and ask for wipo_kind

## Description

The `patentsview` source has been dead since 2026-03-20: USPTO paused its PatentSearch API, and `search.patentsview.org` no longer resolves (checked 2026-11-08: NXDOMAIN). Every PatentsView search failed at the connection. This is the upstream drift #268 describes, reported there by the operator of PatentRef.

This PR restores the source by pointing it at a live endpoint that speaks the same grammar, and fixes a field-name bug that a strict server rejects.

## Changes Made

- **Default endpoint** `https://patentref.io/api/v1/patent/` (PatentRef). It is an **independent third party, not USPTO**, in free beta: US grants from 1976 on, no pre-grant publications, and a free key allows 1,000 requests a month and 45 a minute. This is disclosed in the adapter doc comment, the missing-key error, the README and the CHANGELOG.
- **Configurable endpoint.** `SourceConfig` gains an optional `base_url` (`[patentsview] base_url` in `config.toml`), with `SCITADEL_PATENTSVIEW_URL` as an env override. `build_adapters_with_field` now takes the PatentsView `SourceConfig` instead of its key, so the URL reaches the adapter. This follows the existing `with_base_url` pattern in the OpenAlex, Crossref and DataCite adapters. The two callers (CLI, MCP) are updated; `build_adapters_full` keeps its signature.
- **`patent_kind` → `wipo_kind`** in the `f` list and in response parsing. Verified against PatentRef's published OpenAPI (`components.schemas.PatentFields`, API 1.21.0): `wipo_kind` is a `PatentRecord` field and `patent_kind` is not. All nine requested fields are checked in the schema.
- **Error detail.** A non-2xx response includes the grammar's `X-Status-Reason` header, which carries the reason for a 400.
- **Key hint.** Points at `https://patentref.io/docs/migration.html` instead of `patentsview.org/apis/purpose`, which now 301s to `data.uspto.gov/support/transition-guide/patentsview`.

Out of scope: the rest of #268 (live contract tests and the scheduled CI job for every adapter).

## [Comment #2](https://github.com/vig-os/scitadel/pull/312#issuecomment-6721741169) by [@gerchowl](https://github.com/gerchowl)

_Posted on November 8, 2026 at 12:53 PM_

### Round-2 review fixes — host-bind the stored patentsview key (`cbf3c41`)

Blocker was real: `.scitadel/config.toml` is found via the toplevel (`scitadel-core/src/config.rs:~320`), a cloned repo could commit `[patentsview] base_url = "https://attacker.example/..."`, that passed the https validator, and the keychain-stored key would then be POSTed to the attacker as `X-Api-Key`. Separately, a USPTO key stored before PatentRef existed was silently being forwarded to `patentref.io`.

#### Fix: bind the stored key to a host (and refuse everything else)

- **Store**: `scitadel auth login patentsview` grows `--host <host>` (default `patentref.io`) and writes the host under `patentsview.api_host` in the same secret store as the key; `auth logout patentsview` clears both; `--host` is a no-op for other sources so shared CI scripts aren't broken. `--host` is validated shallowly (no `://`, no `/`, no whitespace) on the CLI side; the real policy is centralised. The secret never rides argv (#248-style storage).
- **Resolve**: new `scitadel_core::config::resolve_patentsview_adapter(file_api_key, file_base_url)` returns a `PatentsViewAdapterConfig { api_key, base_url, bound_host, legacy_unbound }`:

  | key source           | URL source       | `bound_host`                       |
  |----------------------|------------------|------------------------------------|
  | keychain + binding   | —                | `Some(stored_host)`                |
  | keychain, no binding | —                | `Some("search.patentsview.org")` + `legacy_unbound = true` |
  | env                  | env or default   | `None`                             |
  | env                  | **file**         | `Some("patentref.io")` → refuses   |
  | file                 | —                | `None`                             |
  | none                 | —                | `None`                             |

  The resolution is carried on `Config::patentsview_adapter` (`#[serde(skip)]`).
- **Enforce at build time**: `build_adapters_with_field` now takes `&PatentsViewAdapterConfig` and runs `enforce_patentsview_host_binding` after `validate_patentsview_base_url`. A mismatch is `CoreError::Config`; the adapter is NOT built, so no request is ever made. The legacy-unbound case uses a migration-specific message pointing at `https://patentref.io/docs/migration.html`.

#### Nits

1. **CHANGELOG** — dropped the misleading "PatentsView-grammar mirror that accepts the existing key" clause; the new entry describes host-binding, the env-key policy, and that a legacy stored key is NOT silently forwarded to PatentRef — the user is told to request a PatentRef key and re-log in.
2. **patentsview.rs** — fixed the backwards comment: the request uses `wipo_kind`, not `patent_kind`.
3. **URL echoing in errors** — both `validate_patentsview_base_url` and the 3xx `Location` echo now print only `scheme://host[:port]` via shared sanitisers (`url_origin_for_display` in `lib.rs`, `sanitise_redirect_location` in `patentsview.rs`). `userinfo` (`user:pass@`), path and query never reach the error, so a bearer token smuggled into any of them can't ride into logs.
4. **Redirect test** — now asserts the specific error (adapter tag, Location origin, 302, `X-Api-Key` reason) AND that the path/query are stripped (test redirect carries `?token=sekrit`, assertions `!contains("/steal")`, `!contains("token=")`, `!contains("sekrit")`). The redundant `the_posted_body_contains_wipo_kind_and_lacks_patent_kind` test is removed; the literal `expected_request_body` matcher and the source-level `request_body_asks_for_wipo_kind_not_patent_kind` already assert both.

#### Tests

Four new, all required by the brief:

- `a_bound_key_refuses_a_different_configured_host_and_makes_no_request` — wiremock mounts NO matchers; refuse is asserted plus `received_requests().len() == 0`.
- `a_bound_key_accepts_a_matching_configured_host` — binds to `127.0.0.1`, server answers, parse works.
- `a_legacy_unbound_key_is_refused_against_the_default_endpoint_with_the_migration_message` — asserts the message names `search.patentsview.org`, `https://patentref.io/docs/migration.html`, and `scitadel auth login patentsview`.
- `the_patentsview_host_binding_round_trips_through_the_file_backend` — stores, re-stores (rebind), deletes.

#### Docs

- **README** — new `#### Host-bound keys` subsection under `PatentsView endpoint` covering `--host`, the env-key policy, and migrating from a pre-#268 key.

#### Env-var consistency

Documented and implemented: `SCITADEL_PATENTSVIEW_KEY` is sent only when `base_url` also comes from the env or the default. A `base_url` in a repo `.scitadel/config.toml` is NOT authority for an env-set key to reach that host — the operator must bind the key with `auth login --host <host>` instead.
