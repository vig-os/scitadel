# [PR 280](https://github.com/vig-os/scitadel/pull/280) feat(adapters): deterministic preprint routes, and an honest acquisition status

Partial progress on #260. Closes the preprint half and the "no route tried ≠ no access" half; **does not** close the 52-DOI OA-publisher criterion, and says so below.

## The bug

A preprint is free by construction. The ladder missed all three of a real corpus:

| DOI | outcome |
|---|---|
| `10.1101/2025.06.14.659707` | `needs_user_fetch` |
| `10.1101/2024.11.19.624167` | `needs_user_fetch` |
| `10.1101/2024.10.10.615955` | `needs_user_fetch` |

Not an access problem — there was **no preprint route**, so a null `best_oa_location.pdf_url` from OpenAlex ended the walk.

## I measured the transforms, and one assumption in the issue was wrong

The issue described a `biorxiv`/`medRxiv` route pair. There is no such choice to make:

**`10.1101` covers both servers, and medRxiv's own server serves nothing.** `www.medrxiv.org/content/<doi>` returns **403 to every User-Agent**, because that path doesn't exist there — it redirects to `/node/`. Meanwhile:

```
https://www.biorxiv.org/content/10.1101/2025.06.14.659707v1.full.pdf  → 200 application/pdf   (bioRxiv)
https://www.biorxiv.org/content/10.1101/2024.10.10.615955v1.full.pdf  → 200 application/pdf   (a medRxiv DOI!)
https://www.medrxiv.org/content/10.1101/2024.10.10.615955v1.full.pdf  → 403
```

So every `10.1101` DOI routes to **biorxiv.org**, and a test asserts no candidate ever names `medrxiv.org`.

**arXiv needs the prefix stripped.** `arxiv.org/pdf/2301.00001` → 200 (765699 B); `arxiv.org/pdf/arXiv.2301.00001` → **406**.

**ChemRxiv has no deterministic transform** and returns none with the reason recorded — rather than a guessed URL.

Each rule cites the URL and the observed status, in the spirit of `policy.rs`'s "a policy table with unattributed numbers is one nobody can audit".

## "No route tried" is not "no access" (issue item 3)

Status is derived from **per-leg outcomes**, not from the walk ending empty:

| Status | When |
|---|---|
| `pending` | nothing went on the wire, or a route applied and was gated. ADR-007 §2's own word, so **no migration**. |
| `unavailable` | **only** when every *attempted* leg was refused by the place itself (4xx, excluding 408/429) |
| `error` | asked, but no yes/no: transport failure, pacing refusal, login redirect, 5xx, **or an index that answered 200 and named no OA location** |

That last row is the bug: a null index field is a fact about *the index*, not evidence about the work. It can never produce `unavailable` — verified by mutating the condition and watching `only_a_walk_whose_every_evaluated_route_refused_is_unavailable` fail.

`reason` enumerates every leg in walk order, including the "not applicable" ones.

`needs_ill` was deliberately **not** used: this ladder evaluates six of the ADR's routes, so claiming "no route exists" would be #261's overclaim in a new place.

## One more thing, out of the stated scope

A successful download now retracts the full-text want **in the same transaction**, double-scoped (`kind='fulltext' AND locator='' AND drop_path IS NULL`) so it cannot take back the flat importer's rows. Without it a re-download left `coverage` reporting a full text already held — the divergence ADR-007 §1 forbids. Version is deliberately not in the scope: a preprint download satisfies a `vor` want.

## Not fixed: the 52-DOI set

MDPI, RSC, OUP/NAR, PNAS and NIST are untouched, because **their URLs are not derivable from a DOI**. NIST's `nvlpubs.nist.gov` path and OUP's `academic.oup.com` article-pdf path both carry data the identifier does not. That is #253/#254's index-based work; I did not fake a transform.

What did change for those papers: they now record `pending`/`error` instead of a no-access verdict, so **the human list stops lying in the worst direction** even before that work lands — which was the issue's actual "why this matters".

## Also not done

The `coverage` / `action_list` **commands** still don't read `acquisition_state` — that's S2. This fixes the data they will read, not the report.

## Verification

752 tests across 26 binaries, green. `fmt --check` clean. Clippy `-D warnings` clean on the pinned 1.98.1 toolchain.

One existing test was **changed, and it is stricter**: `only_arxiv_may_claim_a_version` → `only_the_preprint_servers_may_claim_a_version`, which now pins the *set* {Arxiv, Biorxiv} permitted to claim `preprint`, so a third route slipping in fails the test. No test was weakened.
