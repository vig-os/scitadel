# [PR 339](https://github.com/vig-os/scitadel/pull/339) fix(cli): scitadel download <doi> records an artefact

## Problem

S2e (#287) retired the legacy dual-write so `record_download` no longer writes `papers.local_path` / `download_status` / `last_attempt_at`. `scitadel download <doi>` went through the **non-recording** DOI-only path; before S2e the legacy columns were the only thing it ever wrote, so now it records nothing at all. A user who runs it gets a downloaded file and an unchanged library, and the paper does not show as downloaded.

## Fix

`scitadel download <doi>` has a distinct, still-needed behaviour that `scitadel acquire` does not cover: it accepts a raw DOI without a prior `papers` row. So it is kept, and routed through the same shared helper acquire uses.

`PaperDownloader::download_by_doi(openalex, doi, output_dir)`:

1. Reuses the existing `papers` row that carries this DOI, when there is one. `find_by_doi` is case-insensitive, so a row seeded with a mixed-case DOI is reused on a lowercase re-download.
2. Otherwise asks OpenAlex and saves what it returns.
3. Otherwise walks the identity chain (OpenAlex → Crossref → DataCite) and mints a minimal row with whichever registry's title answers; when no registry registers the DOI the title stays empty, which `identity::verify` honestly reports as `Unverified` ("no title on one side") and the gate still allows filing.

Then calls `download_paper(&paper, out_dir)` — the same recording ladder `scitadel acquire` uses. Bytes land in the blob store beside an `artefacts` row that names them (ADR-007 §1). On a fetch that ends without bytes, the row minted in step 3 is deleted (scoped at the SQL level by `NOT EXISTS (… artefacts WHERE paper_id = …)` so a row that gained an artefact between mint and cleanup is left alone), so `scitadel show`/`coverage` are never left with a stub.

Both the CLI's `commands::download` and the MCP's `download_paper_tool` DOI branch migrate to this.

`--output-dir` is deprecated. It used to choose where the legacy orphan file landed in `papers/<stem>.<ext>`; #289's recording path writes every byte into the content-addressed blob store under the library root, so a user-chosen directory would be an empty hole next to a file the caller never sees. The flag is still accepted for one release — passing it prints a one-line stderr warning that names the directory the caller asked for and points at `scitadel export` / `scitadel acquire` — and it is removed next release.

## Deleted, so a stale read cannot hide

- `PaperDownloader::download(doi, output_dir)` — the non-recording DOI-only path.
- `write_download_output` — the helper that wrote orphans into `papers/`.
- The `paper: Option<&Paper>` branch in `finish`: it now takes `&Paper`, and a DOI-only path writing an orphan is a **compile error** rather than a quietly wrong answer.
- The leg helpers that only fed the removed path: `try_preprint`, `preprint_candidate`, `preprint_bases`, `try_unpaywall`, `download_publisher_html`, `download_body`. The recording path uses `resolve.rs`'s preprint candidates instead; those still work.
- `Fetched::path` (set by every leg, used by none), the `let _ = path;` and `PathBuf::new()` placeholder in `finish`, and the duplicate `find_by_doi` call that followed an OpenAlex hit.

## Other paths that write into the library without a row

Grepped `fs::write` / `store_blob` / `library_root` across the adapter crates. **None.**

- `scan`/`import_flat`'s `store_blob` writes the content-addressed blob; the same flow writes the `artefacts` row.
- `manifest::write` writes the per-paper mirror JSON file after the DB commit; `scitadel gc` reconciles it, and it is regenerable.
- The `blobs/.tmp` staging the download path uses is in `store_bytes` and `renamed` into place inside the same transaction.

## DOI case-insensitive dedup

`papers.doi` has `idx_papers_doi` as a case-sensitive unique index. DOIs are case-insensitive per the DOI Handbook (§2.4) and every scitadel-owned write path routes DOIs through `normalize_doi` (strip the resolver prefix, lowercase), but data can still arrive from an adapter that only strips the prefix — `openalex.rs:work_to_candidate` did until this PR. Two independent fixes:

- `SqlitePaperRepository::find_by_doi` now compares on `unicode_lower(doi) = unicode_lower(?1)` so a mixed-case stored row is found by a lowercase lookup.
- `openalex.rs:work_to_candidate` routes OpenAlex's DOI through `normalize_doi` so new writes land lowercase.

## Tests

Nine tests against the wiremock-backed fixture (`crates/scitadel-adapters/src/download.rs`), plus a CLI test (`crates/scitadel-cli/tests/download.rs`).

#289 acceptance:

- `download_by_doi_records_exactly_one_artefact_naming_the_file` — one DOI fetched = one artefact row; `DownloadState::FullText` via ADR-007 §1's derivation; reported path is the blob; nothing in `papers/`.
- `download_by_doi_reuses_the_existing_paper_row` — a row that already carries this DOI is written against, not duplicated.

Review wave:

- `download_by_doi_falls_back_to_crossref_for_the_title` — Blocker 1, Crossref answers so the minimal row carries Crossref's title.
- `download_by_doi_leaves_the_title_empty_when_no_registry_answers` — Blocker 1, nothing answers so the title is empty, not the DOI.
- `download_by_doi_populates_the_row_from_an_openalex_match` — Blocker 1, the OpenAlex-found branch.
- `download_by_doi_served_pdf_title_corroborates_crossref` — a PDF with a readable `/Title` passes the post-fetch check against Crossref's title.
- `download_by_doi_is_idempotent_against_a_second_call` — a second download writes no duplicate `artefacts` row.
- `download_by_doi_matches_a_mixed_case_existing_row` — case-insensitive DOI lookup.
- `download_by_doi_failure_cleans_up_the_placeholder_row` (renamed from `…_writes_no_orphan_file`) — asserts the stub `papers` row is gone on a failed fetch.
- `download_output_dir_prints_deprecation_warning` + `download_without_output_dir_emits_no_deprecation_warning` (CLI) — the Blocker 2 warning surface.
