# [PR 305](https://github.com/vig-os/scitadel/pull/305) fix(acquire): an author manuscript of a preprint work ranks as a preprint

#260, option (a). ADR-007 §3's `OA VoR > AM > preprint` rule has always applied to any author-manuscript candidate a repository names. Its motivating case is *a published article*: prefer the accepted manuscript over a preprint of the same work.

That reasoning needs something to prefer. It does not transfer to a bioRxiv posting, where bioRxiv **is** the publication and a second copy held by an index is a duplicate rather than an upgrade.

`epmcAuthMan: Y` on a PPR record means "we hold the author's version of this preprint". The words are identical to the MEDLINE case and the sentence they complete is different.

## Where the decision is made

At the point a repository's flag becomes a `Version`, not in the comparator. `preprint_am_is_a_preprint` downgrades `AuthorManuscript` to `Preprint` when — and only when — the **work-level** signal is a stated preprint type.

The work-level signal is the only thing that can make the distinction: a repository flag says which copy *that service* holds, and cannot know whether a better version exists elsewhere. `source: PPR` and Crossref's `posted-content`/`subtype: preprint` are both consulted before the flag is trusted, and both spellings agree on every probe in `oa_live.rs`.

## What is deliberately left standing

- **`VersionOfRecord` from a repository** — a stronger claim; whether it is right for a preprint work is a different question.
- **`Unstated`** — nothing to downgrade, and Europe PMC vouching for a copy it declines to characterise is a positive statement.
- **An untyped work** — "we do not know what this is" is not evidence that it has no version of record. Widening the gate past a *stated* preprint type would move every untyped work down a rung on no evidence.

`Rank` is unchanged. The 128-cell ordering test still pins `version > licence > fetch step`, because what changed is the *data* on one class of candidates.

## Measured, and the honest number

Rank 1 was a PubMed citation page **2/3** before, **0/3** now. Rank 1 is a preprint-version document **3/3**, and the plan line names both facts:

```
version preprint [europepmc says `author-manuscript copy of a preprint work`]
```

Clause 1's bioRxiv PDF is rank 1 for **1/3** — `10.1101/2024.10.10.615955` obtained a 206 with `application/pdf`. The other two rank a preprint document from an OA source at an earlier fetch step (Europe PMC step 1, PMC step 3) and obtained bytes there, with the bioRxiv transform at rank 4-5 — *named*, not chosen. Both returned Cloudflare HTML on one run and real bytes on another, so "obtained as PDF" for those two is flaky rather than settled.

That is what option (a) was chosen to do, and it is the limit of it: after the downgrade the two **tie** on version and licence, so the fetch order decides, and Europe PMC is step 1. Reaching 3/3 needs a separate decision — whether a preprint server outranks an index for a preprint work — which ADR-007's fetch order currently answers the other way. Recorded in the ADR amendment rather than resolved here.

## Tests

Three, in the shape of their neighbours: the downgrade itself (asserting the source names both facts), the `am` rung surviving for a `journal-article`, and the AM surviving when no registry typed the work. Each was checked by disabling the amendment: the downgrade test fails, the other two still pass — which is the point of having them.

**The first fixture passed vacuously until it was fixed.** It omitted `hitCount`, so `parse_search` returned `Unreadable`, Europe PMC contributed nothing, and the bioRxiv DOI transform carried every assertion alone. The guard `any(candidate.route == EuropePmc)` is in the test now, with a comment saying it is there because of that.
