# [PR 299](https://github.com/vig-os/scitadel/pull/299) feat(acquire): one reading-route filter and the ADR's fetch order as tie-break

#260's measured failure, from #297's live harness (16 DOIs, each with provenance):

> 4/16 obtained by bytes; 3 of those 4 were a DataCite JSON manifest, not a PDF.
> 11 of 13 remaining failures had an obtainable candidate at rank 2–3.

Dominant cause: the **ranker**, not a missing route.

## Rank 1 was filing plagiarism endpoints as the version of record

For a `10.1101/*` preprint, Crossref declares `type: posted-content` and stamps its link `content-version: vor` and `intended-application: similarity-checking`. The ranker read `vor`, outranked the bioRxiv route's own `preprint`, and picked `syndication.highwire.org` — which 403s. `crossref.rs` parsed `intended_application`; nothing read it.

### `intended-application` is now an allow-list, and the one allowed value is the ADR's own filter

ADR-007 §3's resolve bullet already reads `link[intended-application=text-mining]`. Measured values in the wild:

| value | fate | reason |
|---|---|---|
| `text-mining` | keep | sanctioned TDM route, §3 step 5 |
| `similarity-checking` | drop | plagiarism endpoint, not a reading route |
| `syndication` | drop | **undocumented** in Crossref's own format spec — a deny-list from the docs would have harboured it. Every sample duplicated a `similarity-checking` URL |
| `unspecified` | drop | "no purpose stated" is not a purpose. Cost: one real APS accepted-manuscript route no longer surfaces as a candidate |

## Rank gains a third key, and it is exactly ADR-007 §3's fetch order

ADR-007 §3 spells a "Fetch order" — Europe PMC, PMC-OA, OA repositories, SI, TDM, publisher landing page, browser session — that the ranker **has not been applying**. On exact version+licence ties it was declaration order. `Rank { version, licence, fetch_step }`, with `fetch_step` derived from the route and, for the four identity sources, from the URL where §3 names one: `pmc-oa-opendata…` → 2, `europepmc.org` → 1, `doi.org` → 6. A `doi.org` candidate can no longer beat a repository copy on an exact tie.

`fetch_step` can only tie-break: version strictly dominates licence as wave 2 settled, now pinned over the full 128-cell (version, licence, step) space.

## What the live probe table says now

| | bytes | obtained as a **PDF** |
|---|---|---|
| before | 4/16 | 1/16 |
| this branch | 15/16 | 6/16 |

0 regressions. The 6 new PDFs arrive via `pmc-oa-opendata`, for MDPI, PNAS, and a tie-broken OUP. The contract test now floors on a **sniffed** PDF — a first pass that copied #297's declared content-type counted S3's `binary/octet-stream` as non-article and would have reported this as no wins at all.

## What this does NOT fix

**`#260` clause 1 is still 0/3.** Clause 1 is the bioRxiv PDF route, and the blocking cause has always been a Crossref bug that moved: Crossref no longer surfaces bioRxiv as `intended-application: text-mining` for these DOIs, but OpenAlex's `best_oa_location` files the same paper's **PubMed citation page** as `locations[].version = publishedVersion`. The ranker cannot tell a citation page from a reading location without a `Candidate::kind` field (the equivalent of #291's missing write structs). Filed as **#298**.

**§3 gaps surfaced, not papered:** no rung for DataCite's work-level landing page (`DataCite` placed at 3 as the honest reading), `ManualUrl` below step 6, `Biorxiv` at step 3 as a named reading of §3, and step 4 numbered-and-empty — `the_step_4_rung_is_numbered_and_empty` fails the day someone silently wires SI into a wrong rung.
