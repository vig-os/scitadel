# [PR 290](https://github.com/vig-os/scitadel/pull/290) refactor(core): retire the legacy dual-write; readers resolve through artefacts

S2e for #253 — the last of its scope. Retires the legacy dual-write and moves every reader onto `artefacts`.

## Deleted, so a stale read cannot hide

`Paper`'s three fields, `update_download_state`, and the `DownloadStatus` enum are **removed rather than deprecated**, so any remaining reader is a *compile error* instead of a quietly wrong answer. That turned "what still reads these columns?" from an `rg` into a compiler check — the only version of that question worth trusting.

`record_download` now writes one shape in one transaction, and the legacy `papers/<stem>.<ext>` copy is gone: `store_bytes` stages fetched bytes in the store's own `blobs/.tmp/` and renames them in, so **the blob is the file** — one copy, atomic, nothing to clean up.

Every reader moved. `find_cached_file` and `read_paper` resolve `artefacts` → `blobs.rel_path`; the TUI state column and `O` derive from `sqlite::coverage` — the same module `coverage` and `action_list` read, not a second derivation. `O` mattered especially: left on `paper.local_path` it would have opened the last pre-S2e file for every paper, which is a plausible-looking wrong answer rather than an error.

## The upgrade path, verified rather than assumed

Checked against the backfill source: `scan_legacy_papers` selects every non-empty `local_path`, and `plan_legacy_artefact` records an artefact for any whose extension is in the `kind` vocabulary, copying the file into `blobs/`. So an existing library resolves with nothing to do — and a test seeds the legacy shape end-to-end to prove it rather than trusting the reading.

Three real cases, each answered:

| case | answer |
|---|---|
| a file at `papers/<stem>.<ext>` that **no column pointed at** | the one genuine behaviour change. The old resolver found it *by filename alone* and would have extracted a **paywall stub as the paper's text**. ADR-007 §1 already names the mechanism: `scitadel scan`. Documented as a one-time post-upgrade step. |
| extension outside the vocabulary (`.docx`) | `scitadel attach --kind …` |
| recorded path, file gone | kept with `missing_on_disk = 1`; the state column says `Missing` rather than pretending |

## Untrusted text — the part of #287 that was buildable here

`scitadel_core::untrusted`: `Provenance` + `UntrustedText`, whose **`Display` is the neutralised form**, so `{}` is the safe way to render and `as_str()` is the only route to raw bytes (which the manifest mirror needs, since it must stay faithful).

Strips CSI, OSC including **OSC 8 hyperlinks**, DCS/APC/SOS/PM, charset designations and bare ESC; removes control characters; collapses whitespace; caps at 200 chars with a visible ellipsis. Invisible formatting characters — bidi overrides, zero-width, BOM — are stripped too: same class, same boundary, and leaving them out would be a half-measure.

Pinned by a test carrying CSI, `ESC[2J`, an OSC 8 hyperlink, a charset designation, a window-title OSC and a bidi override; plus an **end-to-end** test that writes a real hostile `.caption.txt`, imports it through the real importer, reads it back and renders it.

Deliberately **not** added: a third `Provenance` variant for "dropped in file". `source` is `served_page` for an HTTP fetch and a dropped file alike, so the row cannot tell them apart, and a marker implying otherwise would be a lie the type cannot keep.

## The tape gate was not leaned on

The state-column change is genuinely user-visible, so this does **not** claim `[tape-exempt]`. `papers-download-state.tape` was updated to seed artefacts and a gap row instead of the legacy columns — same four glyphs — and the mapping is pinned by a test.

A GIF could not be rendered here (`ttyd` and `ffmpeg` are both absent), so the next best thing was done: **all nine of the tape's SQL statements were replayed against a real `scitadel init` database** and execute cleanly, and the seeded rows are exactly the four derived shapes. **CI still has to render it** — flagging that plainly rather than claiming the tape passes.

## Three tests replaced, all asserting the bug

- `a_download_records_the_artefact_and_the_legacy_columns_together` → asserts the columns are **not** written
- `a_successful_download_writes_an_artefact_and_the_legacy_columns` → same
- `dry_run_writes_nothing_and_calls_nothing` kept its name but its `legacy_columns` assertion became **whole-`papers`-row equality** — checking three columns nothing writes would have passed vacuously

## Follow-ups filed alongside, not left in this body

- **#287** — the reader's provenance display, TUI chrome, and `read_paper`'s MCP return wording. Deliberately not in this PR.
- **#289** — `scitadel download <doi>` records no artefact, so it no longer marks the paper downloaded. It never recorded one; the legacy columns were the only thing it wrote. Options are to make it record, or to deprecate it in favour of `acquire`, which is paced, identity-checked and idempotent.
