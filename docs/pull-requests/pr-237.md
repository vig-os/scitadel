# [PR 237](https://github.com/vig-os/scitadel/pull/237) fix(mcp): accept short IDs in every ID-accepting tool (#232)

## Summary

- Every ID-accepting MCP tool (`add_search_terms`, `save_assessment`, `assess_paper`, `prepare_assessment`, `prepare_batch_assessments`, `get_papers`, `export_search`, `summarize_search`, `get_paper`, `read_paper`, `get_annotated_paper`, `download_paper`, `get_references`, `get_citations`, `create_annotation`, `create_paper_note`, `reply_annotation`, `update_annotation`, `delete_annotation`, `list_annotations`, `list_unread`, `mark_seen`, `mark_thread_seen`, `toggle_star`, `set_star`, `rekey_paper`) now accepts a full id OR a unique short prefix, routed through one shared resolver. Closes the silent bug where an agent copying the 8-char id printed by `create_question` / `list_questions` / `list_searches` got `Question '<id>' not found.` from every exact-lookup tool.
- Prefix lookup is done in the DB layer via indexed `id GLOB '<prefix>*'` scans capped at LIMIT 2 (enough to distinguish unique / ambiguous / not-found) — not the older list-all-then-scan pattern in the only pre-existing resolver (`resolve_question_id` for bib snapshots).
- `create_question`, `list_questions`, `list_searches`, `get_papers`, `prepare_batch_assessments`, `assess_paper`, `save_assessment` all now print the full 32-char id so the id an agent copies verbatim hits the exact-match fast path; the prefix fallback covers older copy-pasted ids. Ambiguous-prefix errors list both candidates.
- Preserved error message shape (`Question '<id>' not found.`) so downstream consumers pattern-matching on it keep working. Also fixed a latent secondary bug in `read_paper` where the cache-write ran against the raw (possibly prefix) arg and silently no-op'd against the PK.
