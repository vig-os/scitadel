# [PR 306](https://github.com/vig-os/scitadel/pull/306) fix(reader): an untrusted-content envelope for the body itself

The last item #287 deferred. ADR-007 §1's envelope requirement is now implemented for **every field the product renders**: titles, authors, and bodies.

`Paper.r#abstract` and `Paper.full_text` were plain `String` — publisher-controlled (`citation_abstract`, extracted text, landing-page text), reaching a terminal and a tool return unescaped.

## Why a separate type, not `UntrustedText` reused

`UntrustedText` does two jobs and only one is security:

- `strip` — escape sequences, control characters, invisible formatting. **Security.**
- `rendered()` — then **collapses whitespace** and caps at 200 characters. **Presentation.**

For a body the second half is wrong in both halves: collapsing whitespace destroys paragraph structure, and a 200-character cap truncates a document to nothing — one security fix traded for a document-corruption bug.

`UntrustedBody` shares `strip` and **nothing else**. No whitespace collapsing, no length cap. `UntrustedText`'s 200-character cap was never wrong; it is correct for a title, a label and a caption, and that is precisely why one type could not serve both purposes. Its semantics and its test suite are unchanged.

`Display` is the safe form — the same invariant #303 established. Body truncation stays a caller's job (`read_paper`'s `max_chars`, the views' `truncate`), never the type's, because a type that silently truncates a document is a corruption bug.

## Verified by disabling the neutralisation

**19 tests across six crates fail** with `UntrustedBody::rendered()` returning the stored text untouched: `scitadel-core`, `scitadel-adapters`, `scitadel-mcp`, `scitadel-tui`, `scitadel-scoring`, and a doc test. All pass with it enabled.

Worth recording *how* that number was obtained, because I got it wrong first: my initial grep of `cargo test --workspace` counted **1**, which was an artifact — the workspace run stops at the first failing test binary. `--no-fail-fast` is required to count a mutation across crates. The subagent's figure of 12 was an undercount for the same reason.

Ten call sites are render paths and go through `rendered()` **by name** — which is why the `Display` revert alone moves only one test, and why the `rendered()` mutation is the one that actually pins this. Seven call sites are data paths and stay on `as_str()` with a comment each: the `papers` columns, dedup's abstract comparison, `bibtex`, `csl_json`, `csv_export`, bib-import merge. A truncated citation record is a corrupted citation record.

## A body that is only escape sequences survives as empty

`"\u{1b}[2J"` renders as the empty string. The invariant is one-directional: you may lose content you never had, but you never invent content that was not there. No `[removed]` marker, because that would put a string in front of a reader that the publisher never wrote.

## Three things recorded rather than silently resolved

- **The TUI reader renders the whole body** into one `Paragraph` with no scroll offset. Pre-dates the envelope; **not a security fault**, because an uncapped body reaches a terminal *neutralised*. Paging it is its own slice.
- **MCP `build_annotated_paper` returns the whole `full_text`** with no `max_chars` to honour — larger than `read_paper`'s 20k default.
- **`CandidatePaper.r#abstract` is still `String`.** It is the pre-dedup transport, not a `Paper` field, so the envelope stops where #303's did.

The ADR amendment records all three, marks the full-text envelope and prompt-injection framing (added as prose in the scoring prompt) as implemented, and leaves style stripping out with its reason.
