# [PR 293](https://github.com/vig-os/scitadel/pull/293) feat(acquire): resolve then rank — one metadata pass, ranked, one fetch

Wave 2 of #254 (S3): ADR-007 §3's central claim, which was not implemented.

> A metadata pass (which touches no publisher hosts) finds every candidate location. The ladder then chooses by **version and licence, not by whichever route answered first.**

The ladder tried routes in order and took the first hit, so a preprint route that answered beat a version of record one hop later — exactly backwards.

## Version strictly dominates licence

`Rank` is a two-field tuple with a derived `Ord`, and the derivation *is* the rule — no weight table, nothing to tune.

A licence says **permission to reuse**; a version says **which document we would be holding**. Interleaving lets a CC-BY preprint outrank an all-rights-reserved VoR, `acquire` closes a `vor` want with it, and coverage reads the library as holding the article of record. No weight fixes that, because the axes are not the same kind of quantity — a licence strength cannot be added to a version.

**The cost is named, not buried:** a CC-BY preprint outranks an all-rights-reserved author manuscript, which is wrong for a read-only-but-not-reuse user. That is a licence *filter*, and `Rank` is a plain two-key tuple precisely so a caller can filter without touching it.

## An unrankable candidate is labelled, not guessed

`Candidate::version` is an `Option`, and the comparator operates on a type that cannot hold one — so `unwrap_or` inside it is a **compile error, not a lint**. Unranked candidates land in `Resolution::unranked` with a reason and never enter `ranked`. A user sees:

```
  – not ranked: http://…/repo/copy.pdf via openalex (named by openalex locations[3])
    — version unstated — no registry typed it and the DOI prefix implies no version
```

`Unstated` is a **rung, not a hole**: ADR-007 §3 step 6 fetches a publisher landing page "for OA works only", which is a statement about *when*, not about version. It is deliberately **not** the column word `unknown`, which stays migration 013's word for "no route established a version".

## The re-fetch loop — and it was worse than I first spotted

I flagged this after reading the diff: `version_satisfies("vor", "unknown", route)` only holds for `legacy`/`import_flat`, so a ranked VoR candidate fetched via `publisher` filed as `unknown`, did **not** satisfy the `vor` want, and the next run ranked it again and fetched it again — forever. The headline feature of the slice produced an infinite re-fetch.

The agent reproduced the loop before fixing it:

```
p-vor|fulltext_pdf|unknown|full_text|unpaywall|1|0
```

then with the re-queue in place, the second run planned the work again.

**Investigating it turned up something larger: no route could file `am` at all**, and 11 of 13 fetching routes filed `unknown`, which satisfies *no* version-specific want. One write fixes all of it:

```rust
let version = write.version.or_else(|| write.route.artefact_version())
```

The **resolver's value wins** when they disagree — a route knows what kind of server served the bytes and nothing about what the bytes are; the resolver read the version off the location it chose. `Some(Unknown)` ("looked, nothing stated") and `None` ("did not look") take different paths on purpose, so "no answer" stays distinguishable from "no question".

`access_basis` deliberately did **not** gain a field: it has one producer, so #261's rule is still enforced by there being nowhere to put a second.

## The loop test asserts the loop

```rust
let requeued = queue_add(&fx.db, &["p-vor".into()])?;
let before = fx.request_count().await;
let second = fx.acquire(&AcquireRequest::queue()).await;
assert!(second.plan.works.is_empty(), …);
```

The second half is what makes it a loop test rather than a happy-path test.

## One cost you should weigh

`dry_run_writes_nothing_and_calls_nothing` asserted `request_count == 0`, which cannot survive "a dry run shows the ranked plan". It became `dry_run_writes_nothing_and_touches_no_publisher`.

**A dry run now spends four `Meta` requests per planned work** — metadata budget only, zero publisher contact, and the output says so rather than claiming "no requests". That is a deliberate trade: you cannot show a ranked plan without doing the resolve. The network half of the test is the *stronger* claim, since "touches no publisher" is what the requirement actually is.

## A fixture bug that mattered

One fixture named a candidate at the relative URL `{}` — harmless as a fall-through miss, **fatal as a ranked choice**. `is_fetchable_url` now guards at five collection sites, and `data:`, `file:///etc/passwd` and `mailto:` are all rejected: a parse-only check would pass all three, and a `file://` URL is a local file read wearing a network budget.

## Four tests replaced, all asserting the thing #254 exists to change

Including `a_preprint_doi_is_fetched_before_the_openalex_leg` → `a_version_of_record_beats_a_preprint_regardless_of_route_order`: it asserted the preprint route was fetched *because it came first*. Under resolve-then-rank no request order decides anything.

## Not here

The `am` want still has no **producer**: `queue_add` and `import_flat` both hard-code `vor`. That is a policy change about what the system asks for, not a correctness fix, so I did not bundle it. Wave 3 (Europe PMC / PMC-OA candidates) is what makes #260's VoR half reachable.
