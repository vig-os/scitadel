# [PR 281](https://github.com/vig-os/scitadel/pull/281) test(vhs): repair the export-keybind tape, which had been silently testing nothing

Fixes the red `dev` build. The distinct-snapshot gate failed on `tui-export-keybind` with **all four frames byte-identical** — the failure mode that gate exists to catch.

## Three staleness bugs, each failing *silently*

Inside a VHS tape, an `sqlite3` error scrolls past and the run continues, so a broken seed looks like a working one until something asserts on the *absence* of output — which is exactly what this gate did.

| # | Tape said | Reality |
|---|---|---|
| 1 | `INSERT INTO shortlist (…)` | the table has been **`shortlist_members`** since migration 010 → "no such table" |
| 2 | `(…, added_at, updated_at)` | `shortlist_members` has **no `updated_at` column** → "no such column" |
| 3 | seeded `'$USER'` | `scitadel tui` reads the reader from `$USER`, falling back to the literal `"unknown"`. A vhs shell does not reliably export it, so the seed could write `reader=''` while the TUI looked for `reader='unknown'`. Now pinned to `demo`. |

The shortlist was therefore always empty, `E` reported `export failed: shortlist is empty`, and the dashboard never opened — **so the tape asserted nothing about the feature it is named for.**

## The navigation was stale too

```diff
-# Tab → Tab → Tab to land on Questions.
+# Tab twice to land on Questions.
```

Written when the strip had three tabs. It has four now (`Searches | Papers | Questions | Queue`), so three presses **overshot onto Queue**, where `E` and `Enter` are both no-ops — which is *why* frames 02 and 03 came out identical. `question-dashboard.tape` already used two; this now matches it.

## Verification

| | unique frames |
|---|---|
| before | **1** (gate fails) |
| after, 3 consecutive local runs | 3, 4, 4 |

The gate fails only when *every* frame is identical, so this is a stable pass rather than a lucky one.

### A process note

My first local reproduction was invalid: `cargo build --release -p scitadel` fails (there is no package named `scitadel` — it is `scitadel-cli` with `[[bin]] name = "scitadel"`), so `target/release/scitadel` did not exist and the tape silently fell through to a **`scitadel 0.7.0` binary from the Nix store** on `PATH`. I was debugging the wrong build. Worth knowing that the tape's `PATH="$PWD/target/release:…"` will happily run a stale installed binary when the release build has failed.

## Known gap, stated rather than papered over

The final frame still shows `export failed: shortlist is empty` in my local runs, so **the tape is not yet exercising a successful export**. That is a further defect in either the tape's seeding or the export path, and deciding which is real work I have not done. This PR repairs a tape that was testing nothing; it does not add coverage of the `E` keybind.
