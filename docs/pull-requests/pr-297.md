# [PR 297](https://github.com/vig-os/scitadel/pull/297) test(adapters): a live contract harness for the OA route set

Groundwork for #268, and the measurement #260's acceptance clause needs — they want the same thing.

`contract-tests` was declared and gated nothing. PR #270 removed the unreachable CI job *and* the empty feature that made it look meaningful, so `cargo test --features contract-tests` was a **hard error**, not a no-op. There has been no API-drift detection at all.

## The gate cannot rot

#268's acceptance requires the difference be asserted by a test, because a feature gating nothing is what made E4 invisible. So the empty case fails in the **default, offline** suite:

```
the gated file declares 0 live tests; the gate must cover real work,
and an emptied gate is what #268 is about
```

I proved it by emptying the gated file and watching that fail. **1034 → 1039.**

The probe table is deliberately **ungated** — a gated table can be emptied silently, and an empty table makes a live suite report 100% over nothing.

## Read-only structurally

No `Database`, no blob store, no artefact row. `PolicyPacer` reads the shipped `BucketPolicyTable` and enforces the real intervals and caps, so a contract test can't quietly become an unthrottled crawler.

`Obtained` / `NotObtained` / `NetworkError` / `NoCandidate` are kept apart. A location the plan ranks #1 that answers **403** is `NotObtained`, not obtained; a source we could not ask is `NetworkError`, not "unreachable". The #261 overclaim rule, applied to the measurement itself.

## Every DOI has a provenance line

16 DOIs, each tagged `Issue260` or `LiveQuery`, with `LIVE_QUERY_PROVENANCE` recording the exact Crossref/DataCite query for the 9 not in #260's body.

That discipline exists because **my earlier measurement of these same prefixes was wrong** — I invented half the sample and inferred registry ownership from which API 404'd. A DOI with no source line is not evidence.

## What it measured

**4 of 16 obtained.** Against #260's 7 named DOIs: **2**.

**Clause 2 is unmeasurable as written.** #260 names 7 DOIs and asserts "the 52-DOI set above" — the 52 are never enumerated. The 16-DOI set is a cited proxy, not the criterion.

The dominant cause is **the ranker, not a missing route**:

| DOI | rank 1 | fetch | what would have served |
|---|---|---|---|
| 3× `10.1101/*` | `syndication.highwire.org` | 403 | #2 `pubmed.ncbi.nlm.nih.gov` → **203, 5590 B** |
| `10.3390/pharmaceutics14051098` | `mdpi.com/…/pdf` | 403 | #3 `pmc-oa-opendata` → **206, 1024 B** |

11 of 13 failures have an obtainable candidate sitting at rank 2 or 3.

## Two findings that change #260's diagnosis

**Publisher-direct routes (#260 proposal item 2) would not fix these.** Measured with both a bare and a browser User-Agent:

```
mdpi.com/1999-4923/14/5/1098/pdf                      -> 403
pnas.org/doi/pdf/10.1073/pnas.2415658122              -> 403
academic.oup.com/clinchem/article-pdf/39/3/467/…pdf   -> 403
pubs.rsc.org/en/content/articlepdf/2026/QO/D5QO01181G -> 403
```

These are **bot walls, not paywalls**. The works are already in the plan, in PMC-OA and Europe PMC. #260's diagnosis — "the ladder has no preprint route" — was right for 2026-09 and is now stale for everything except the *ranking* of the route that does exist.

**The bioRxiv regression is one unparsed field.** Verified live:

```
10.1101/2025.06.14.659707   type: posted-content, subtype: preprint
  link[0]: content-version: vor | intended-application: similarity-checking
              -> syndication.highwire.org/content/doi/…
```

Crossref declares the work a preprint, then attaches a **plagiarism-detection endpoint stamped `content-version: vor`**. The ranker reads `vor`, outranks the biorxiv transform's `preprint`, picks it, and it 403s. `crossref.rs:353` already parses `intended_application`; **nothing consumes it.** That is 0/3 → 3/3 on clause 1 and is a separate change from this one.
