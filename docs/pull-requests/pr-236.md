# [PR 236](https://github.com/vig-os/scitadel/pull/236) chore(repo): adopt devkit governance hooks + activate core.hooksPath

## Summary

Closes #228 — adopts the five devkit-shipped hooks that never made it into
this repo's preserved `.pre-commit-config.yaml` when devkit 1.6.0 was carried
forward in #207, and wires `.githooks/` as the git entry point on dev-shell
entry so those hooks actually fire.

**Stacks on #235 (Rust toolchain pin)** — both touch `flake.nix`, and this
branch is built on top of that one. The diff below shows all three commits
until #235 merges to `dev`; look at the tip commits (`5cf7983` and `2f713de`)
for the PR-2 delta, or review #235 first. No functional dependency: if #235
lands first this PR rebases cleanly; if this lands first #235 needs a trivial
rebase.

## Hooks added

Matching devkit 1.17.0's template `entry` / `stages` / `pass_filenames`
exactly:

| Hook | Stage | Why |
|---|---|---|
| `validate-commit-msg` | commit-msg | Conventional Commit + `Refs:` gate. Local backstop for the CI `validate-commit-range` job — same rule set, one round trip shorter. |
| `check-agent-identity` | pre-commit | Rejects author / committer identities on `.github/agent-blocklist.toml`. Same list the CI `commit-checks` job uses. |
| `prepare-commit-msg-strip-trailers` | prepare-commit-msg | Strips attribution trailers (`Co-authored-by:` / `Assisted-by:` / `Generated-by:`) before the validate hook or CI ever see the message. |
| `nixfmt` | pre-commit | This repo owns `flake.nix`, so it has real work to do. |

**`just-fmt` remains disabled.** Reverified on devkit 1.17.0: a fresh
`just --fmt --unstable` still reflows the comment blocks around `set shell`
and around `with-native-libs`, both of which live in the managed banner and
would trip the Scaffold Drift gate. The reason to keep the hook off is
identical to #207's; the comment on the retired block records the recheck so
the next devkit bump can reevaluate cheaply.

## Dev-shell + shellHook changes

- **`pkgs.nixfmt`** added to the dev shell (canonical spelling —
  `nixfmt-rfc-style` is now an alias with a deprecation warning) so the
  language:system hook resolves from PATH in every mode.
- **`core.hooksPath` wiring** added to `shellHook`. The upstream investigation
  found the root cause: devkit's `mkProjectShell` normally supplies the
  `githooksPathHook` fragment (vig-os/devkit#1112) but this repo uses
  `pkgs.mkShell` directly and never inherited it. So every fresh
  direnv / `nix develop` session here has been leaving `core.hooksPath` unset
  and the commit-side gates silently inert — the state the issue's
  "possibly the #1463 worktree-start interaction" hint pointed at, but not
  because of worktree-start; because the fragment was never in the shell to
  begin with.

  The wiring copies devkit's exact guards so the two never fight over the
  setting: `.githooks/` must exist, MAIN worktree only (git-dir ==
  git-common-dir), only when the value differs. Linked worktrees stay the
  sole responsibility of `just worktree-start` (#1463).

- `flake.nix` is now nixfmt-clean under the new hook (mostly whitespace: the
  outputs argument list and the packages list moved onto their own lines).

## Verification

- `prek run --all-files` -> all hooks Passed (branch-name, all pre-commit
  built-ins, yamllint, shellcheck, actionlint, shellcheck-composite-actions,
  pymarkdown, cargo fmt, `nixfmt`, `check-agent-identity`, typos).
- Prepare-commit-msg trailer-stripping hook fed a message with an attribution
  trailer strips it as expected; the follow-up `commit-msg` stage passes the
  cleaned message.

- Scratch-repo simulation of the `shellHook` logic (main-worktree shape:
  git-dir == git-common-dir, `.githooks/` present) sets
  `core.hooksPath = .githooks` on first entry and is idempotent on the
  second; a linked worktree (git-dir != common-dir) is left untouched.
