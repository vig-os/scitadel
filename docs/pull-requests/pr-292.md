# [PR 292](https://github.com/vig-os/scitadel/pull/292) feat(adapters): Crossref and DataCite identity adapters, and the pre-fetch chain

Wave 1 of #254 (S3). Resolve-then-rank and the OA routes are later waves — this PR is the two identity adapters and the chain that uses them.

## My premise was half wrong, and probing corrected it

I measured that six of ten unresolvable DOIs were preprint/repository DOIs *"that Crossref 404s"*, and concluded DataCite holds the preprint-server prefixes. **It does not.** The implementing agent re-probed and:

| DOI | OpenAlex | Crossref | DataCite |
|---|---|---|---|
| `10.1101/2025.06.14.659707` (#260) | 200 | **200** | 404 |
| `10.1101/2024.11.19.624167` (#260) | 200 | **200** | 404 |
| `10.1101/2024.10.10.615955` (#260) | 200 | **200** | 404 |
| `10.18434/m32154` (OSTI, #260) | 200 | 404 | **200** |
| `10.5281/zenodo.23162961` | 404 | 404 | **200** |
| `10.26434/chemrxiv.15000484/v1` | 200 | **200** | 404 |

`10.1101` and `10.26434` are registered to **Crossref** — `10.26434` has 56,845 `posted-content` records as a Crossref member. DataCite holds the *repository* DOIs.

**The conclusion survives on half the evidence, and that is the useful half.** #260's misses split cleanly:

- `10.18434` / `10.5281` — **only DataCite can corroborate these**, which is this PR.
- `10.1101` — Crossref already answered. Those two failures were never about identity; they were about **routing**, which #280 fixed.

So DataCite is required for a genuinely missing case, just not the one I asserted.

## The trap is on DataCite, not Crossref

My brief said "a 404 carrying a JSON error object is a trap" and pointed it at both. Measured:

- Crossref 404 → `text/plain`, 19 bytes, `Resource not found.` — not JSON, so `serde_json` refuses it. **Safe by luck.**
- **DataCite 404 → `application/json`, 87 bytes, and valid JSON**: `{"errors":[{"status":"404",…}]}`. A parser that inspects the body before the status finds no `data`, and if it defaults, hands the matcher three `None`s — so every preprint reads `unverified` and the chain ends a hop early.
- OpenAlex 404 → 207 bytes of HTML.

Two independent gates now prevent it. `PacedClient` refuses any non-2xx before a body is reachable, so "not registered" is decided **on the status alone**; and each parser independently requires its success envelope (`message`, `data.attributes`, `id`), so even a 200 carrying an error document yields no record. Pinned separately *and* together.

## One parser, two call sites

The OpenAlex parse moved out of `download.rs` into `openalex.rs`, so the pre-fetch chain and the download leg share it. A second parser would be a second answer to "what does this registry call the work".

## Reused rather than rebuilt

The `crossref` and `datacite` bucket rows **already existed** in `policy.rs` with sourced values — not duplicated. Added instead: provenance re-recorded from a re-probe, and a test that the hosts the adapters actually use are routed **by policy**. Unrouted, `api.crossref.org` resolves to a bucket bearing its own name while silently carrying the 5 s unknown-host policy — the exact trap the `doi.org` row exists to document.

`Endpoints` is now the single authority for three more hosts, so wave 2's metadata pass routes through it instead of building URLs.

## Five existing tests were re-scoped, not weakened

They broke on request counts. Each was re-scoped to the **ladder** with the chain's hops counted and asserted separately — which strengthens them. `an_arxiv_doi_is_fetched_from_the_stripped_url_with_no_index_lookup` now pins the `Meta`/`Oa` split across the chain too.

## Handed to the later waves

- Crossref publishes rate-limit headers on the single-record route (`x-rate-limit-limit: 10`, `x-api-pool: polite-single` — the polite pool is *observable*). DataCite publishes **none**, so its interval rests entirely on the documented figure.
- Crossref's `license[]` and DataCite's `relatedIdentifiers` are already reachable through these adapters — the parsers deliberately ignore them, so wave 2 gets a tested, paced, bucketed transport rather than a new one.
- Crossref `type: posted-content`/`preprint` and DataCite `types.resourceTypeGeneral` are a far better version signal than inferring from the DOI prefix, which is what the preprint leg does today.
- **The `Unreadable`-stops / `NotRegistered`-continues rule is what resolve-then-rank most needs**: one metadata pass then rank is a fall-through chain, and a transient 500 must not read as "nothing here".

## Bug found beyond this slice

`IdentityChain::new` initially ignored the test seam's bases, so tests escaped onto the live internet and the real Crossref answered with a real record. Nothing caught it because there was no `wiremock` fixture — so **any adapter added without a `with_base_url` seam has the same failure mode.**

## Verification

957 tests across 27 suites, green (44 new). `fmt --check` clean. Clippy `-D warnings` clean on the pinned 1.98.1 toolchain. No existing test weakened.
