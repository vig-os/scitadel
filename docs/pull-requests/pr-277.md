# [PR 277](https://github.com/vig-os/scitadel/pull/277) fix(http): redact credentials from error values, not just from messages

Closes #276.

## The leak

The OpenAlex key travels as a **query parameter** (`?api_key=…`), so it was present in every error string built from a request URL — rendered in the TUI's task panel, returned verbatim to an MCP agent that may log it or paste it into a transcript, and captured by `tracing`.

Nothing logged a "key", which is why auditing for printed credentials never found it: the credential was simply *inside a URL*, and URLs are treated as non-sensitive everywhere.

`FetchError` already documented that carrying the URL rather than the whole request meant "a credential can never reach an error string". That reasoning is correct for header-based credentials and **wrong** for query-parameter ones.

## Two leak paths, not one

**1. The URL field.** Every URL-bearing variant now stores a redacted URL. Redaction happens where the value is *stored*, not where it is printed: `FetchError` derives `Debug`, so redacting in `Display` alone would leave the secret in the struct, reachable from any `{:?}` — including test failure messages.

**2. The source field.** `reqwest::Error` embeds the request URL in both its `Display` and its `Debug`, so an error rendering `{source}` hands the key straight back no matter how `url` is treated. The source is now wrapped in `TransportSource`, whose formatting is a URL-free classification (`connection failed`, `timed out`, …), with the typed error still reachable via `error()` for `is_timeout`/`is_connect`/`status`.

This makes the leak **structurally impossible** rather than merely guarded — storing a bare `reqwest::Error` no longer compiles:

```
error[E0308]: mismatched types
193 |  source: source,
    |  ^^^^^^^^^^^^^^^ expected `TransportSource`, found `Error`
```

## Verification

The end-to-end test makes a real request with `?api_key=…` to a closed port and asserts the credential is absent from **both** `Display` and `Debug`. It earned its place: it caught the `{source}` path above *after* the first round of fixes had already gone green on `Display` alone.

| Test | Pins |
|---|---|
| `a_credential_in_the_query_never_reaches_a_transport_error` | the real path, end to end, both formatters |
| `debug_cannot_leak_either` | derived `Debug` is a leak path |
| `credential_shaped_parameters_are_caught_whatever_the_spelling` | `api_key`, `apikey`, `api-key`, `x-api-key`, `access_token`, `insttoken`, `client_secret`, `password`, `signature` |
| `a_fragment_can_also_carry_a_token` | OAuth-callback fragments |
| `authority_credentials_are_stripped` | `https://user:pass@host` |
| `a_url_with_no_credentials_is_returned_unchanged` | no false positives |
| `unparseable_input_is_not_echoed` | conservative answer for non-URLs |

Redaction costs no debuggability, and a test asserts that: the host, path and non-credential parameters survive, since they are what makes an error actionable.

728 tests pass across 26 binaries. `fmt --check` clean. Clippy `-D warnings` clean on the pinned 1.98.1 toolchain.
