# [PR 214](https://github.com/vig-os/scitadel/pull/214) ci(release): register devkit release-train entry points on main

GitHub only registers `workflow_dispatch` workflows that exist on the default branch. The devkit 1.6.0 migration (#208) adds `prepare-release.yml` / `release.yml` / `promote-release.yml` on `dev`, so without this the first release on the train cannot be dispatched at all (devkit's first-release runbook assumes older copies already exist on `main`).

- Copies the three entry points **verbatim** from #208 — all are `workflow_dispatch`-only, so nothing fires on `main` events.
- Dispatches run with `--ref dev` (prepare) and `--ref release/X.Y.Z` (release, promote), so the dev-side workflow graph (`release-core`, extensions, …) is what executes.
- The release merge to `main` later lands identical files — no conflict.

Refs #207
