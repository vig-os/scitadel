Two companion issues, one mechanism: every consumer of a DOI list was re-implementing shape checking, and one downstream project already had two hand-maintained publisher prefix tables that had begun to diverge.

## DOI shape validator (#262)

`validate_doi_detailed` returns `Ok(canonical)` or a `DoiRejection` naming **why**, so a caller can report a rejection for a human to overturn instead of silently dropping the candidate. `validate_doi` remains as a boolean wrapper.

The rule set is deliberately **permissive about suffix structure**, because the real identifier families disagree and plausible-looking rules reject valid DOIs:

| Family | Example | Naive rule that breaks it |
|---|---|---|
| Elsevier compact | `10.1016/0003-2670(93)90142-7` | treating `)` as punctuation |
| ACS pre-2008 | `10.1023/b:josl.0000026645.41309.d3` | truncating at first `:` |
| OUP segmented | `10.1093/nar/gkv1075` | "suffix has no slash" |
| ChemRxiv | `10.26434/chemrxiv.…/v1` | "first slash splits prefix" |

So there is deliberately **no** slash rule and **no** colon rule. What it rejects: unbalanced brackets, ellipsis placeholders, illegal characters, and repository record URLs.

`UnbalancedBracket` is its own case because the truncated half still starts with `10.` and still passes a prefix check — that is how nine DOIs reached a fetch queue. All ten from the run are in the tests, plus the stray-closing-bracket mirror case.

## Publisher table (#261)

`classify_publisher` returns `PublisherVerdict::Known` or an **explicit** `Unknown` carrying the offending prefix — never a default that reads as knowledge. The registry is a curated subset of doi.org registrant prefixes with a provenance note; being incomplete is acceptable because the incompleteness is visible and `ALL_PUBLISHERS` plus a coverage test keep it honest.

`route_verdict` splits the two-valued verdict into four, keeping *unknown* apart from *known absent*. **The acceptance criterion:** no note may ever assert "no TDM route available" for a publisher the ladder never classified.

```
10.1039/d0nr01234a   → NoTdmRouteAvailable { Rsc }     "…has no TDM route available (classified…)"
10.1016/j.jneumeth…  → TdmKeyMissing     { Elsevier }  "…set SCITADEL_ELSEVIER_TDM_KEY"
10.99999/some.12345  → PublisherUnknown  { "99999" }  "publisher not classified… no route was evaluated"
```

`HostKind` marks preprint servers separately from publishers, since they are free by construction — the distinction #260's route list depends on. A test fails if one is ever re-typed.

## Ingest, and one normalizer

- `dedup` validates with the detailed form, logs the reason, and takes the canonical DOI from the same call so a candidate can never be keyed on the raw string.
- `scitadel-export` had a **second** `normalize_doi` handling the `doi:` CURIE but not `dx.doi.org`, while core's handled the reverse — so the same DOI keyed off either form did not converge. It now delegates to one implementation covering all six prefix forms. This was a latent bug found while working #261, not something either issue mentioned.

## Verification

Every new rejection rule was confirmed to fail when the rule is removed:

| Rule removed | Failing test |
|---|---|
| unbalanced bracket | `rejects_the_truncated_dois_from_the_raid_run`, `rejects_a_stray_closing_bracket` |
| record-URL detection | `rejects_a_repository_record_url` |

Two of my own tests caught real bugs while being written, both fixed: `…` was reported as an invalid character rather than an ellipsis placeholder, and my first record-URL heuristic used an uppercase-segment test that normalisation had already lowercased. The shipped-ChEMBL-identifier case (`10.6019/chembl12345`) is asserted to still pass, so the rule is not a blanket slash ban.

22 new tests. Full suite green (23 binaries). `fmt --check` and clippy clean for the touched crates.
