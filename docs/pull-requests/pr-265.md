# [PR 265](https://github.com/vig-os/scitadel/pull/265) fix(mcp): drop the agent-supplied output_dir from download_paper

## Problem

`DownloadPaperRequest` (`crates/scitadel-mcp/src/server.rs:316`) carried an `output_dir` that `download_paper_tool` (`tools.rs:584`) passed straight through to `PaperDownloader`. Any agent driving the MCP server — including a prompt-injected one — chose where attacker-influenced bytes landed: `~/.config/autostart`, a repo's `.githooks/`, a shell rc directory. The content is publisher HTML, or whatever a DOI resolves to.

## Fix

- `output_dir` is removed from the request, so it is gone from the **JSON schema an LLM actually reads**. Tightening only the Rust signature would have left the tool description implying the capability existed and invited agents to keep sending it.
- Downloads always resolve to the configured `papers_dir`. The filename was *already* derived from the paper's own identifiers (`doi_to_filename` / `sanitize_filename`), and neither can emit a path separator — so no caller-controlled path component survives.
- The human CLI keeps `scitadel download --output-dir`, where the destination comes from a person who can see what they are downloading.

## Sibling findings (not fixed here)

The same scan surfaced two more caller-controlled paths on the MCP surface. Both are the same class, but both are load-bearing for agent workflows, so I've filed them separately rather than change three tool contracts under this issue:

- `ImportBibRequest.path` — agent-supplied file **read**
- the bib export request's output path — agent-supplied file **write**

## Verification

Both tests confirmed to fail when `output_dir` is reintroduced:

| Test | With field | Without |
|---|---|---|
| `download_paper_schema_offers_no_output_directory` | FAILED — `output_dir is back in the MCP schema` | pass |
| `download_paper_request_ignores_a_supplied_output_dir` | FAILED | pass |

The schema test asserts the remaining properties are exactly `["doi", "paper_id"]`, so a future field cannot quietly reintroduce a path. The second test confirms an injection-style payload carrying `/home/victim/.config/autostart` parses successfully but leaves nothing on the struct to forward.

A caller that still sends `output_dir` has it **ignored rather than obeyed** — no `deny_unknown_fields` is used anywhere in this crate, and tolerating extra keys is the house convention.

Full workspace suite green (23 test binaries). Clippy clean for the touched crates under the pinned 1.98.1 toolchain; under the locally-installed 1.95 it reports a pre-existing unknown-lint in `scitadel-mcp` that is present on `origin/dev`.
