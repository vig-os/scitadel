# [PR 218](https://github.com/vig-os/scitadel/pull/218) fix(deps): upgrade rmcp 0.17 -> 3.4.1 for security advisories

Clears the rmcp Dependabot advisories (part of #215):
- rmcp < 1.4.0 — DNS rebinding in the Streamable HTTP server transport
- rmcp < 2.0.0 — OAuth protected-resource validation; unauthenticated session-table leak
- rmcp < 2.1.0 — custom headers leaked to cross-origin redirect targets

scitadel only enables `server` + `transport-io` + `macros` (the stdio server behind `scitadel mcp`), so exposure was small — but 0.17 was three majors behind.

**API migration (3.x):** `Implementation`, `ProgressNotificationParam`, `ResourceUpdatedNotificationParam` and `ServerInfo` (now `ServerConfig`) are `#[non_exhaustive]`, so they are built via `::new(…)` / `.with_*()`; `get_info` returns `ServerConfig`. `#[tool_router]` / `#[tool_handler]` / `#[tool]` / `Parameters<T>` are unchanged; scitadel-cli needed no edits.

**Wire behaviour:** stdio smoke test (`initialize` → `tools/list`) before vs after — same 41 tools, names, descriptions, input-schema properties and `required` lists, same capabilities and server info. Only difference: `inputSchema.title` (the internal Rust struct name) is no longer emitted.

**Verified** with the CI toolchain (rustc 1.98.1): fmt clean, `clippy --workspace --all-targets -D warnings` clean, `cargo test --workspace` 517 passed.

Refs: #215
